# 🎮 Plano de Engajamento e Retenção Anti-Evasão

> **Disciplina:** Introdução à Programação — Curso Técnico em Desenvolvimento de Sistemas
> **Objetivo:** Eliminar a frustração inicial e construir uma jornada de aprendizado suave, gamificada e motivadora que impeça o aluno de desistir nas primeiras semanas.

---

## 1. Matriz de Progressão Suave — A Jornada Sem Frustração

### 🧭 Princípio Central

> A evasão acontece quando a distância entre "o que sei" e "o que me pedem" é grande demais.
> A solução é criar uma **rampa de acesso**, não uma escada íngreme.

```
Nível de Dificuldade
     ▲
     │                                    ╭── Fase 4: Mini-Projeto
     │                              ╭─────╯
     │                        ╭─────╯ Fase 3: Código Real
     │                  ╭─────╯
     │            ╭─────╯ Fase 2: Pseudocódigo
     │      ╭─────╯
     │ ─────╯ Fase 1: Visual/Blocos
     │
     └───────────────────────────────────────────────▶ Tempo (semanas)
         Sem1-2      Sem3-4        Sem5-7       Sem8-10
```

### 🟢 Fase 1 — Gamificação Puramente Visual (Semanas 1–2)

| Item | Detalhe |
|------|---------|
| **Objetivo** | Desenvolver raciocínio lógico SEM escrever código |
| **Ferramentas** | Code.org (Hora do Código / Minecraft), Scratch |
| **Conceitos trabalhados** | Sequência, repetição (loop), condicionais (se/senão) |
| **Formato** | Arrastar e soltar blocos visuais |
| **Entrega do aluno** | Completar fases no Code.org + criar mini-jogo no Scratch |

#### O que o aluno sente nessa fase:

> "Programar é como montar um quebra-cabeça! Eu consigo!"

#### Atividades específicas:

- [ ] Aula 1: Code.org — Labirinto do Minecraft (sequência + repetição)
- [ ] Aula 2: Code.org — Artista (loops com padrões geométricos)
- [ ] Aula 3: Scratch — Criar animação simples (gato que anda e fala)
- [ ] Aula 4: Scratch — Mini-jogo (pegar objetos caindo) com condicionais

#### 🎯 Meta de engajamento:

> 100% dos alunos completam pelo menos 1 projeto funcional nesta fase. Isso gera a **primeira conquista** e ancora o sentimento de "eu sou capaz".

### 🔵 Fase 2 — Lógica Estruturada e Pseudocódigo (Semanas 3–4)

| Item | Detalhe |
|------|---------|
| **Objetivo** | Traduzir o pensamento visual em fluxogramas e escrita lógica |
| **Ferramentas** | Flowgorithm + Portugol Studio |
| **Conceitos trabalhados** | Variáveis, tipos de dados, entrada/saída, condicionais escritos, loops escritos |
| **Formato** | Desenhar fluxograma → escrever em Portugol |
| **Entrega do aluno** | 3 programas funcionais no Portugol Studio |

#### Ponte didática (conectar ao que já sabem):

| No Scratch (Fase 1) | No Flowgorithm (Fase 2) | No Portugol (Fase 2) |
|---------------------|--------------------------|----------------------|
| Bloco "mova 10 passos" | Retângulo de Atribuição | `x = x + 10` |
| Bloco "se tocou na borda" | Losango de Decisão (If) | `se (x > 100) { }` |
| Bloco "repita 10 vezes" | Hexágono (For loop) | `para (i=1; i<=10; i++)` |
| Bloco "pergunte e espere" | Paralelogramo (Input) | `leia(nome)` |

#### Atividades específicas:

- [ ] Aula 5: Flowgorithm — Fluxograma da média escolar
- [ ] Aula 6: Portugol — Traduzir o fluxograma para código escrito
- [ ] Aula 7: Portugol — Sistema de desconto (Se/Senão encadeado)
- [ ] Aula 8: Portugol — Tabuada com laço Para

## 2. Dinâmicas de Sala de Aula Anti-Frustração

---

### ⚡ Estratégia "Primeiros 15 Minutos" — A Vitória Rápida

#### Princípio:

> Nos primeiros 15 minutos, o aluno DEVE ter sucesso em algo. Esse micro-sucesso gera dopamina e engajamento para o restante da aula.

#### Estrutura padrão de abertura:

| Tempo | Ação | Objetivo Emocional |
|-------|------|--------------------|
| 0–3 min | **Warm-up:** Mostrar algo legal/engraçado feito com código (meme, site bizarro, easter egg) | Curiosidade + "código faz coisas legais" |
| 3–8 min | **Quick Win:** Desafio de 5 min que TODOS conseguem (copiar e colar código e ver funcionar, completar 1 fase no Code.org, corrigir 1 erro simples) | Sensação de competência |
| 8–15 min | **Conexão:** "Na aula passada vocês fizeram X. Hoje vamos adicionar Y" | Continuidade + propósito |

#### Banco de Quick Wins (ideias prontas):

| Fase | Quick Win de 5 minutos |
|------|------------------------|
| Fase 1 | Completar 1 puzzle no Code.org |
| Fase 2 | Copiar código do Portugol, rodar e ver funcionando |
| Fase 3 | Mudar a cor de fundo de uma página com 1 linha de JS |
| Fase 4 | Fazer commit e ver no GitHub ("meu código está na nuvem!") |

> 🎯 **Regra de ouro:** O aluno NUNCA deve sair dos primeiros 15 minutos sem ter executado algo com sucesso.

---

### 🚨 Protocolo de Resolução de Erros — O "SOS em 3 Passos"

#### O problema:

> Quando o código dá erro, o aluno iniciante entra em pânico: "Não funciona! Desisto!" A frustração com erros é o **motivo #1 de evasão** nas primeiras semanas.

#### A solução — Cartão SOS (imprimir e colar no monitor):

```
┌──────────────────────────────────────────────────────┐
│           🚨 SOS — MEU CÓDIGO DEU ERRO!              │
│                                                       │
│  PASSO 1: 🔍 LEIA a mensagem de erro                │
│  → Em qual LINHA está o erro?                        │
│  → O que a mensagem DIZ? (mesmo em inglês, tente)    │
│                                                       │
│  PASSO 2: 🤝 PERGUNTE ao colega de dupla             │
│  → "Meu erro está na linha X. Você vê o problema?"  │
│  → 2 minutos de tentativa juntos                     │
│                                                       │
│  PASSO 3: 🙋 CHAME o professor                       │
│  → Explique: "Tentei fazer X, esperava Y,            │
│    mas aconteceu Z"                                  │
│                                                       │
│  ⚠️ PROIBIDO: Apagar tudo e recomeçar do zero!      │
└──────────────────────────────────────────────────────┘
```

#### Por que funciona:

- **Passo 1** ensina a LER erros (habilidade profissional essencial)
- **Passo 2** cria laço social (colega ajuda = menos solidão = menos evasão)
- **Passo 3** garante que ninguém fica travado mais de 5 minutos

#### Implementação em sala:

- [ ] Imprimir o cartão SOS para cada dupla de alunos
- [ ] Na primeira aula, provocar um erro DE PROPÓSITO e resolver junto usando o protocolo
- [ ] Celebrar quando alunos resolverem erros sozinhos: "Quem resolveu um bug hoje? 🎉"

---

### 👥 Pair Programming — Piloto e Co-piloto

#### O que é:

Dois alunos no mesmo computador. Um digita (Piloto), o outro revisa e orienta (Co-piloto). A cada 10–15 minutos, trocam de função.

#### Regras simples para aplicar:

```
┌─────────────────────────────────────────────────────────┐
│            REGRAS DO PAIR PROGRAMMING                     │
│                                                          │
│  🎮 PILOTO (quem digita):                               │
│  • Tem as mãos no teclado                               │
│  • Explica em voz alta o que está fazendo               │
│  • Pode pedir ajuda ao co-piloto                        │
│                                                          │
│  🗺️ CO-PILOTO (quem orienta):                           │
│  • NÃO toca no teclado                                  │
│  • Lê o código e procura erros                          │
│  • Sugere melhorias e próximos passos                   │
│  • Consulta a apostila ou documentação                  │
│                                                          │
│  ⏱️ TROCA a cada 10-15 minutos (usar timer visível)     │
│                                                          │
│  ❌ PROIBIDO:                                            │
│  • Co-piloto tomar o teclado sem autorização            │
│  • Piloto ignorar sugestões sem explicar por quê        │
│  • Fazer em silêncio (a comunicação é obrigatória!)     │
└─────────────────────────────────────────────────────────┘
```

#### Benefícios Anti-Evasão:

| Problema de Evasão | Como o Pair Programming resolve |
|--------------------|---------------------------------|
| "Me sinto sozinho, ninguém me ajuda" | Sempre tem alguém do lado |
| "Sou o único que não entende" | Percebe que o colega tem dúvidas parecidas |
| "Tenho vergonha de perguntar" | Perguntar ao colega é menos intimidante |
| "Não sei por onde começar" | O co-piloto dá direção quando o piloto trava |

#### Como montar as duplas:

- **Semana 1–2:** Duplas por afinidade (escolhem os amigos) → conforto emocional
- **Semana 3–4:** Duplas mistas (professor monta) → aprender com pessoas diferentes
- **Semana 5+:** Rotação livre → autonomia

## 3. Calendário de Mini-Desafios Gamificados

---

### 🏆 Desafio 1 — Scratch Game Jam (Semana 2)

| Item | Detalhe |
|------|---------|
| **Nome** | 🎮 Scratch Game Jam — O Melhor Jogo em 40 Minutos |
| **Objetivo pedagógico** | Consolidar sequência, loops e condicionais; desenvolver criatividade e trabalho em dupla |
| **Ferramenta** | Scratch (scratch.mit.edu) |
| **Formato** | Duplas têm exatamente 40 minutos para criar um mini-jogo funcional. Tema surpresa revelado na hora! |
| **Temas possíveis** | "Fuga", "Coleta", "Labirinto", "Corrida" |

#### Regras:

1. Duplas sorteadas no início da aula
2. Tema revelado com contagem regressiva dramática
3. Timer visível no projetor (40 minutos)
4. Ao final: cada dupla apresenta em 1 minuto
5. Turma vota no jogo mais divertido e no mais criativo

#### Premiação:

| Categoria | Prêmio |
|-----------|--------|
| 🥇 Jogo Mais Divertido | Selo "Game Designer" + certificado impresso |
| 🎨 Jogo Mais Criativo | Selo "Artista do Código" + certificado impresso |
| 🏅 Participação | Todos recebem selo "Scratch Warrior" no mural da sala |

#### Mural de Conquistas:

> Crie um mural (físico ou virtual no Padlet/Miro) onde os selos vão sendo colados ao longo do módulo. O aluno VENDO sua progressão visual reduz dramaticamente a evasão.

### 🏆 Desafio 2 — Detetive de Bugs (Semana 5)

| Item | Detalhe |
|------|---------|
| **Nome** | 🔍 Detetive de Bugs — Quem Encontra o Erro Mais Rápido? |
| **Objetivo pedagógico** | Desenvolver leitura de código, identificação de erros e depuração (debugging). Normalizar erros como parte do processo. |
| **Ferramenta** | Portugol Studio ou JavaScript (VS Code / navegador) |
| **Formato** | Professor fornece 5 códigos com ERROS propositais. Alunos (individual ou dupla) devem encontrar e corrigir todos no menor tempo. |

#### Exemplo de código com bug (JavaScript):

```javascript
// BUG: Encontre o erro!
function calcularMedia(nota1, nota2) {
    let media = nota1 + nota2 / 2  // Erro: faltou parênteses
    return media
}

console.log(calcularMedia(8, 6))  // Deveria dar 7, mas dá 11
```

#### Níveis de dificuldade:

| Nível | Tipo de Bug | Pontos |
|-------|-------------|--------|
| ⭐ Fácil | Ponto e vírgula faltando / nome errado de variável | 10 pts |
| ⭐⭐ Médio | Lógica errada (operador > em vez de <) | 20 pts |
| ⭐⭐⭐ Difícil | Loop infinito / parênteses na ordem errada | 30 pts |

#### Premiação:

| Posição | Prêmio |
|---------|--------|
| 🥇 1º lugar | Selo "Bug Buster Supremo" + pode escolher tema do próximo exercício |
| 🥈 2º lugar | Selo "Detetive de Código" |
| 🥉 3º lugar | Selo "Olho de Águia" |
| Todos que completaram | Selo "Caçador de Bugs" no mural |

#### Efeito Anti-Evasão:

> Transforma a experiência de "erros são frustrantes" em "erros são puzzles divertidos para resolver". Muda completamente a relação emocional do aluno com debugging.

### 🏆 Desafio 3 — Hackathon Relâmpago (Semana 9)

| Item | Detalhe |
|------|---------|
| **Nome** | ⚡ Hackathon Relâmpago — Do Zero ao Deploy em 90 Minutos |
| **Objetivo pedagógico** | Integrar todas as habilidades (HTML + CSS + JS + Git), simular ambiente profissional de entrega sob pressão leve, desenvolver trabalho em equipe |
| **Ferramenta** | VS Code + Navegador + GitHub Pages |
| **Formato** | Equipes de 3 pessoas. Recebem um briefing de "cliente" (professor) e devem entregar uma página funcional publicada no GitHub Pages em 90 minutos. |

#### Briefings de "cliente" (sortear):

| Briefing | Requisito Mínimo |
|----------|-----------------|
| "Quero uma landing page para minha pet shop" | Header + 3 seções + botão funcional |
| "Preciso de um sorteador de nomes para meu chá revelação" | Input de nomes + botão sortear + resultado visual |
| "Crie um conversor de moeda (Real → Dólar)" | Input + cálculo + exibição do resultado |

#### Papéis na equipe (rodízio sugerido):

| Papel | Responsabilidade |
|-------|-----------------|
| 🎨 Designer/HTML | Estrutura e visual da página |
| ⚙️ Dev/JavaScript | Lógica e interatividade |
| 📋 Gerente/Git | Commits, organização, deploy no GitHub Pages |

#### Critérios de avaliação:

| Critério | Peso |
|----------|------|
| Funciona? (roda sem erros) | 40% |
| Está publicado no GitHub Pages? | 20% |
| Visual agradável? | 20% |
| Apresentação clara (2 min)? | 20% |

#### Premiação:

| Categoria | Prêmio |
|-----------|--------|
| 🏆 Melhor Projeto | Selo "Full Stack Iniciante" + certificado assinado |
| 🎯 Melhor Apresentação | Selo "Comunicador Tech" |
| 🚀 Deploy Mais Rápido | Selo "Speed Coder" |
| Todos os participantes | Selo "Hackathon Survivor" + projeto no portfólio |

## 5. Checklist Semanal do Professor (Prevenção Ativa de Evasão)

### 🔔 Sinais de alerta de possível evasão:

- [ ] Aluno faltou 2 aulas seguidas sem justificativa
- [ ] Aluno não entregou a atividade da semana
- [ ] Aluno fica em silêncio durante pair programming
- [ ] Aluno disse frases como "não nasci pra isso" ou "é muito difícil"
- [ ] Aluno mexe no celular durante toda a aula prática

### 🛟 Ações de resgate imediato:

| Sinal | Ação do Professor |
|-------|--------------------|
| 2 faltas seguidas | Mandar mensagem informal no grupo: "Senti sua falta! Semana que vem tem desafio legal" |
| Não entregou atividade | Oferecer 15 min de monitoria individual no intervalo |
| Silêncio na dupla | Trocar de dupla e colocar com aluno comunicativo |
| "Não nasci pra isso" | Mostrar o mural: "Olha quantos selos você já tem! Na semana 1 você não sabia nem o que era variável" |
| Celular na aula | Dar tarefa no celular (Code.org funciona no mobile) |
