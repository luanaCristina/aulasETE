## 📖 Sobre a Disciplina

Esta disciplina aborda os fundamentos de segurança da informação, criptografia, proteção contra ameaças cibernéticas, e os aspectos éticos e legais da tecnologia, com ênfase na LGPD (Lei Geral de Proteção de Dados). Os alunos desenvolverão pensamento crítico sobre privacidade, ética digital e responsabilidade no desenvolvimento de sistemas.

### Tópico 3: Criptografia

#### Criptografia Simétrica vs Assimétrica

```
SIMÉTRICA (mesma chave para cifrar e decifrar):
┌──────┐    🔑 chave    ┌──────┐    🔑 chave    ┌──────┐
│ Texto│ ──────────────→ │Cifrado│ ──────────────→ │ Texto│
│Plano │    CIFRAR       │ #### │    DECIFRAR     │Plano │
└──────┘                 └──────┘                 └──────┘
Algoritmos: AES-256, DES, 3DES
Vantagem: Rápida
Problema: Como compartilhar a chave com segurança?

ASSIMÉTRICA (par de chaves: pública + privada):
┌──────┐  🔑 Chave PÚBLICA  ┌──────┐  🔑 Chave PRIVADA  ┌──────┐
│ Texto│ ──────────────────→ │Cifrado│ ──────────────────→ │ Texto│
│Plano │   do DESTINATÁRIO   │ #### │   do DESTINATÁRIO   │Plano │
└──────┘                     └──────┘                     └──────┘
Algoritmos: RSA, ECC
Vantagem: Não precisa compartilhar chave secreta
Problema: Mais lenta que simétrica

HASH (função unidirecional — NÃO é criptografia reversível):
┌──────┐                 ┌──────────────────────────────────────┐
│ Texto│ ──────────────→ │ a7ffc6f8bf1ed766...51f1e3da0c8a      │
│"abc" │    SHA-256      │ (sempre 64 caracteres hex)           │
└──────┘                 └──────────────────────────────────────┘
Uso: Verificar integridade, armazenar senhas
NÃO dá para "descriptografar" um hash!
```

#### HTTPS — Como Funciona

```
NAVEGADOR                           SERVIDOR
    │                                   │
    │──── 1. "Oi, quero HTTPS" ────────→│
    │                                   │
    │←── 2. Certificado + Chave Pública─│
    │                                   │
    │  3. Verifica certificado (CA)     │
    │  4. Gera chave simétrica         │
    │  5. Cifra com chave pública      │
    │                                   │
    │──── 6. Chave simétrica cifrada ──→│
    │                                   │
    │  7. Servidor decifra com privada  │
    │                                   │
    │←───── 8. 🔒 COMUNICAÇÃO SEGURA ──→│
    │      (tudo cifrado com AES)       │
    │                                   │

✅ Confidencialidade: dados cifrados
✅ Integridade: hash verifica alterações  
✅ Autenticidade: certificado prova identidade
```

### Tópico 4: Defesas — Firewalls, Backup e MFA

#### Firewall — Conceito

```
INTERNET (ameaças)     FIREWALL         REDE INTERNA (protegida)
    🌐                   🧱                    🏢
    │                    │                     │
    │── Tráfego ────────→│                     │
    │   legítimo         │── ✅ Permitido ────→│
    │                    │                     │
    │── Ataque ─────────→│                     │
    │   malicioso        │── ❌ Bloqueado      │
    │                    │                     │

TIPOS:
• Packet Filter: analisa cabeçalhos (IP, porta)
• Stateful: acompanha estado das conexões
• Application Layer: inspeciona conteúdo (WAF)
• Next-Gen (NGFW): combina tudo + AI
```

#### Política de Backup 3-2-1

```
┌─────────────────────────────────────────────────────┐
│           REGRA DE BACKUP 3-2-1                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  3️⃣  TRÊS cópias dos dados                         │
│      (1 original + 2 backups)                      │
│                                                     │
│  2️⃣  DOIS tipos de mídia diferentes                │
│      (HD externo + nuvem, ou SSD + fita)           │
│                                                     │
│  1️⃣  UMA cópia em local remoto (offsite)           │
│      (outro prédio, outra cidade, cloud)           │
│                                                     │
├─────────────────────────────────────────────────────┤
│  TIPOS DE BACKUP:                                  │
│  • Full: cópia completa (lento, ocupa espaço)      │
│  • Incremental: só o que mudou desde o último      │
│  • Diferencial: mudanças desde o último full       │
│                                                     │
│  FREQUÊNCIA SUGERIDA:                              │
│  • Full: semanal (domingo à noite)                 │
│  • Incremental: diário                             │
│  • Teste de restauração: mensal!                   │
└─────────────────────────────────────────────────────┘
```

#### MFA — Autenticação Multi-Fator

```
FATORES DE AUTENTICAÇÃO:

1️⃣ ALGO QUE VOCÊ SABE     → Senha, PIN, resposta secreta
2️⃣ ALGO QUE VOCÊ TEM      → Celular (SMS/app), token físico
3️⃣ ALGO QUE VOCÊ É        → Biometria (digital, face, íris)

MFA = combinar 2 ou mais fatores diferentes

EXEMPLO: Login do banco
  1. Senha (sabe) + 2. Token no app (tem) = 2FA ✅
  
NÃO é MFA: senha + pergunta secreta (ambos são "algo que sabe")
```

### Tópico 5: LGPD — Lei Geral de Proteção de Dados

#### Fluxograma LGPD

```
┌─────────────────────────────────────────────────────┐
│              LGPD — Lei 13.709/2018                 │
│         Vigente desde setembro de 2020              │
├─────────────────────────────────────────────────────┤
│                                                     │
│  ATORES:                                           │
│  👤 Titular → pessoa dona dos dados                │
│  🏢 Controlador → decide como usar os dados       │
│  ⚙️ Operador → processa dados a mando do controlador│
│  🛡️ DPO (Encarregado) → ponte entre titular/ANPD │
│  ⚖️ ANPD → fiscaliza e aplica sanções             │
│                                                     │
├─────────────────────────────────────────────────────┤
│  BASES LEGAIS (quando posso tratar dados):         │
│  1. Consentimento do titular                       │
│  2. Obrigação legal/regulatória                    │
│  3. Execução de contrato                           │
│  4. Legítimo interesse                             │
│  5. Proteção da vida                               │
│  6. Tutela da saúde                                │
│  7. Pesquisa (anonimizado)                         │
│  8. Exercício de direitos em processo              │
│  9. Proteção ao crédito                            │
│  10. Políticas públicas                            │
│                                                     │
├─────────────────────────────────────────────────────┤
│  DIREITOS DO TITULAR:                              │
│  ✅ Confirmação de existência de tratamento        │
│  ✅ Acesso aos dados                               │
│  ✅ Correção de dados incompletos/inexatos         │
│  ✅ Anonimização, bloqueio ou eliminação           │
│  ✅ Portabilidade para outro fornecedor            │
│  ✅ Eliminação dos dados (com exceções)            │
│  ✅ Informação sobre compartilhamento              │
│  ✅ Revogação do consentimento                     │
│                                                     │
├─────────────────────────────────────────────────────┤
│  SANÇÕES (multas):                                 │
│  • Advertência                                     │
│  • Multa de até 2% do faturamento (máx R$ 50mi)   │
│  • Bloqueio ou eliminação dos dados                │
│  • Publicização da infração                        │
└─────────────────────────────────────────────────────┘
```

#### LGPD para Desenvolvedores

```
CHECKLIST DO DESENVOLVEDOR:
┌─────────────────────────────────────────────────────┐
│ ✅ Coletar APENAS dados necessários (minimização)  │
│ ✅ Informar CLARAMENTE a finalidade do tratamento  │
│ ✅ Implementar mecanismo de CONSENTIMENTO          │

│ ✅ Permitir EXPORTAÇÃO (portabilidade)             │

DADOS PESSOAIS vs DADOS SENSÍVEIS:
```

## 💻 Exercícios

### Exercício 1: Identificar Vulnerabilidades (Semana 4)

**Objetivo:** Analisar um cenário e identificar falhas de segurança.

**Cenário:** A escola "Tech Academy" possui um sistema web de notas com as seguintes características:
- Login com usuário e senha (sem MFA)
- Senhas armazenadas em MD5 no banco
- URL para ver notas: `sistema.com/notas?aluno_id=123`
- Sem HTTPS (HTTP puro)
- Backup feito uma vez por mês em pendrive
- Todos os professores usam a mesma senha de admin

**Tarefas:**
1. Identifique TODAS as vulnerabilidades (mínimo 8)
2. Classifique cada uma pelo pilar CIA violado
3. Proponha uma solução para cada vulnerabilidade
4. Priorize as correções (crítica/alta/média/baixa)

**Entrega:** Relatório com tabela: Vulnerabilidade | CIA | Risco | Solução | Prioridade

---

### Exercício 2: Criptografia na Prática (Semana 8)

**Objetivo:** Experimentar diferentes tipos de criptografia.

**Tarefas:**
1. Usar ferramenta online (CyberChef) para:
   - Cifrar mensagem com AES-256 (simétrica)
   - Gerar hash SHA-256 de um arquivo
   - Verificar que alteração mínima muda todo o hash
2. Inspecionar certificado HTTPS de 3 sites (banco, redes sociais, governo)
   - Anotar: emissor, validade, algoritmo, tipo de certificado
3. Explicar por que MD5 não deve ser usado para senhas (pesquisar rainbow tables)
4. Demonstrar a diferença entre criptografia e encoding (Base64 não é segurança!)

**Entrega:** Documento com screenshots + explicações de cada experimento

---

### Exercício 3: Plano de Backup (Semana 10)

**Objetivo:** Criar uma política de backup completa para um sistema real.

**Cenário:** Você é o responsável pelo backup do sistema acadêmico da ETE que contém:
- Banco de dados PostgreSQL (5GB, cresce 100MB/mês)
- Arquivos de trabalhos dos alunos (50GB no Storage)
- Configurações e código-fonte (2GB no Git)

**Tarefas:**
1. Aplicar a regra 3-2-1 detalhadamente
2. Definir frequência (full/incremental/diferencial)
3. Escolher ferramentas e destinos (cloud + local)
4. Criar procedimento de restauração (passo a passo)
5. Definir RTO (Recovery Time Objective) e RPO (Recovery Point Objective)
6. Planejar teste mensal de restauração

## 📝 Simulado

### Simulado — Ética e Segurança da Informação (15 questões)

**1.** Os três pilares da segurança da informação (CIA Triad) são:
- a) Confiança, Inovação, Automação
- b) Confidencialidade, Integridade, Disponibilidade ✅
- c) Criptografia, Internet, Autenticação
- d) Compliance, Infraestrutura, Acessibilidade

**2.** Um ransomware é um malware que:
- a) Rouba senhas do navegador
- b) Criptografa dados e exige pagamento para devolver o acesso ✅
- c) Envia spam pelos seus contatos
- d) Desinstala o antivírus

**3.** Na criptografia assimétrica, para enviar uma mensagem confidencial para Maria, você usa:
- a) Sua chave privada
- b) Sua chave pública
- c) A chave pública de Maria ✅
- d) A chave privada de Maria

**4.** A função hash SHA-256 produz:
- a) Um texto cifrado reversível
- b) Uma chave de criptografia
- c) Um resumo de tamanho fixo (256 bits) que não pode ser revertido ✅
- d) Um arquivo compactado

**5.** A regra de backup 3-2-1 recomenda:
- a) 3 senhas, 2 fatores, 1 admin
- b) 3 cópias, 2 mídias diferentes, 1 cópia offsite ✅
- c) 3 servidores, 2 firewalls, 1 antivírus
- d) 3 backups por dia, 2 semanais, 1 mensal

**6.** MFA (Multi-Factor Authentication) combina fatores de:
- a) Várias senhas diferentes
- b) Categorias diferentes: saber + ter + ser ✅
- c) Vários emails de recuperação
- d) Múltiplos dispositivos do mesmo tipo

**7.** Segundo a LGPD, "dado pessoal sensível" inclui:
- a) Nome e email
- b) Endereço e telefone
- c) Dados de saúde, biometria, orientação sexual ✅
- d) CPF e RG

**8.** O DPO (Data Protection Officer) na LGPD é chamado de:
- a) Controlador
- b) Operador
- c) Encarregado ✅
- d) Fiscal

**9.** SQL Injection é classificada no OWASP Top 10 como:
- a) Broken Access Control
- b) Injection ✅
- c) Security Misconfiguration
- d) Cryptographic Failures

**10.** Phishing é um ataque de:
- a) Força bruta
- b) Engenharia social ✅
- c) Denial of Service
- d) Man-in-the-Middle

**11.** HTTPS garante segurança usando:
- a) Apenas firewall
- b) Certificado digital + criptografia (TLS) ✅
- c) Antivírus no servidor
- d) VPN obrigatória

**12.** A LGPD prevê multa de até:
- a) R$ 10.000 por infração
- b) 2% do faturamento, limitada a R$ 50 milhões por infração ✅
- c) 10% do faturamento sem limite
- d) Apenas advertência, sem multa

**13.** Um firewall do tipo WAF (Web Application Firewall) protege contra:
- a) Vírus no computador local
- b) Ataques na camada de aplicação web (SQL Injection, XSS) ✅
- c) Quedas de energia
- d) Falhas de hardware

**14.** Realizar pentest sem autorização formal é:
- a) Permitido se for para fins educacionais
- b) Crime previsto no Código Penal (Art. 154-A) ✅
- c) Permitido em sistemas governamentais
- d) Uma boa prática de segurança

**15.** O princípio de "minimização" na LGPD significa:
- a) Minimizar o tamanho do banco de dados
- b) Coletar apenas os dados estritamente necessários para a finalidade ✅
- c) Usar o mínimo de criptografia possível
- d) Ter o menor número de funcionários com acesso

1. Professor narra história de Kevin Mitnick: hacker mais procurado dos EUA nos anos 90, usava MAIS engenharia social que código. Preso, depois virou consultor de segurança.
2. Perguntas éticas: "Depois de cumprir pena, ele deveria poder trabalhar com segurança?", "Contratar ex-hackers é ético?", "Existe hacking 'do bem'?"

### 📊 Rubrica de Avaliação Adaptada (Atividades sem Laboratório)

| Critério | Excelente (10-9) | Bom (8-7) | Regular (6-5) | Insuficiente (<5) |
|----------|-----------------|-----------|---------------|-------------------|
| **Compreensão conceitual** | Demonstra domínio de CIA/criptografia/LGPD | Boa compreensão com pequenas lacunas | Compreensão superficial dos conceitos | Não demonstra compreensão |
| **Identificação de riscos** | Encontra todas as vulnerabilidades/riscos | Encontra maioria dos riscos | Encontra apenas os mais óbvios | Não identifica riscos |
| **Pensamento crítico/ético** | Argumentação sólida, múltiplas perspectivas | Boa argumentação | Opinião sem fundamentação | Não participa do debate |
| **Aplicação prática** | Propõe soluções viáveis e bem fundamentadas | Soluções boas com pequenas lacunas | Soluções genéricas/superficiais | Não propõe soluções |
| **Entrega/Documentação** | Completa, organizada, dentro do prazo | Completa com pequenos ajustes | Incompleta mas entregue | Não entregou |

> 💡 **Nota:** Atividades de contingência têm o **mesmo peso** das atividades regulares. Segurança da informação é 90% comportamento humano — não precisa de computador para aprender!
