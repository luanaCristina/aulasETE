## 📚 Material Teórico e Prático

### Bloco 1 — Pesquisa e Empatia (Semanas 1-3)

#### 🔍 O que é Design Centrado no Usuário?

O DCU é uma abordagem de projeto onde **todas as decisões** são tomadas com base em dados reais sobre os usuários — não em "achismos" da equipe.

> 💡 **Analogia do dia a dia:** Imagine um restaurante que cria o cardápio SEM perguntar aos clientes o que eles gostam de comer. Pode até dar certo por sorte, mas provavelmente vai falhar. O DCU é como fazer uma pesquisa de satisfação ANTES de montar o cardápio.

**O ciclo do DCU:**

```
┌─────────────────────────────────────────┐
│                                         │
│    1. PESQUISAR    →  2. DEFINIR        │
│         ↑                   ↓           │
│    4. TESTAR       ←  3. PROTOTIPAR     │
│                                         │
│         (ciclo contínuo de iteração)    │
│                                         │
└─────────────────────────────────────────┘
```

#### 📊 Caso Real: iFood vs. 99Food — Pesquisa de Mercado

| Critério | iFood | 99Food |
|----------|-------|--------|
| **Público-alvo primário** | Classes B/C, 25-45 anos, conveniência | Classes C/D, 18-35 anos, preço |
| **Proposta de valor** | Variedade + velocidade | Menor preço + cupons agressivos |
| **UX principal** | Descoberta (explorar restaurantes) | Objetivo direto (pedir rápido e barato) |
| **Funcionalidade destaque** | Filtros detalhados + avaliações | Cashback e frete grátis |
| **Ponto fraco UX** | Excesso de informação na tela | Poucos restaurantes em cidades pequenas |

> 🎯 **Lição:** O mesmo problema (pedir comida) gera soluções de UX radicalmente diferentes dependendo da **persona** que você está atendendo.

### Bloco 4 — Testes e Iteração (Semanas 15-19)

#### 🧪 Roteiro de Teste de Usabilidade

**Formato:** Teste moderado presencial (com 3-5 participantes)

**Script do Moderador:**

```
1. INTRODUÇÃO (2 min)
   "Olá! Vamos testar um app de agendamento de consultas.
   Não estamos testando VOCÊ — estamos testando o DESIGN.
   Não existe resposta certa ou errada. Pense em voz alta."

2. TAREFAS (15 min)
   Tarefa 1: "Você quer agendar uma consulta com cardiologista.
              Encontre um médico disponível para esta semana."
   Tarefa 2: "Agora cancele essa consulta."
   Tarefa 3: "Encontre seu histórico de consultas passadas."
   Tarefa 4: "Troque sua foto de perfil."
   Tarefa 5: "Encontre um médico que aceite seu convênio (Unimed)."

3. PÓS-TESTE (5 min)
   - "Numa escala de 1 a 5, quão fácil foi usar o app?"
   - "O que mais te confundiu?"
   - "O que você mudaria?"
```

**Métricas a coletar:**

| Métrica | Como medir | Meta |
|---------|-----------|------|
| Taxa de sucesso | % de tarefas concluídas sem ajuda | ≥ 80% |
| Tempo na tarefa | Segundos para completar cada tarefa | < 30s para tarefas simples |
| Erros | Toques errados ou retornos | ≤ 1 por tarefa |
| SUS Score | System Usability Scale (questionário) | ≥ 68 pontos |

### 🔄 Exemplo Prático: Da Persona ao Código

#### Passo 1 — A Persona define a funcionalidade

A persona "Mariana" tem a dor: *"Esquece horários de consultas"*

**Decisão de produto:** Implementar notificações push de lembrete.

#### Passo 2 — No Mobile (Expo/React Native)

```typescript
// src/services/notifications.ts — AgendaPro Mobile
import * as Notifications from 'expo-notifications';

/**
 * Agenda lembrete 24h antes da consulta
 * ORIGEM: Jornada do Usuário → Etapa "Pós-uso" → Oportunidade "Notificação 24h"
 */
export async function agendarLembrete(consulta: {
  medico: string;
  data: Date;
  especialidade: string;
}) {
  // Calcula 24h antes
  const trigger = new Date(consulta.data);
  trigger.setHours(trigger.getHours() - 24);

  await Notifications.scheduleNotificationAsync({
    content: {
      title: '📅 Lembrete de Consulta',
      body: `Amanhã às ${consulta.data.toLocaleTimeString('pt-BR', {
        hour: '2-digit',
        minute: '2-digit',
      })} — ${consulta.especialidade} com Dr(a). ${consulta.medico}`,
      sound: true,
    },
    trigger,
  });
}
```

> 💡 **Conexão:** O comentário no código referencia exatamente a etapa da Jornada do Usuário onde a oportunidade foi identificada. Isso é rastreabilidade design → código.

```html
/**
 * Exibe banner de lembrete se houver consulta nas próximas 24h
 * ORIGEM: Jornada do Usuário → "Pós-uso" → Oportunidade de retenção
 */
function verificarConsultasProximas(consultas) {
  const agora = new Date();
  const em24h = new Date(agora.getTime() + 24 * 60 * 60 * 1000);

  const proxima = consultas.find(c => {
    const dataConsulta = new Date(c.data);

}
```

#### Passo 4 — No Backend (Python/Flask)

```python
# app/services/notificacao_service.py — API de lembretes
"""
ORIGEM DO REQUISITO: Persona "Mariana" → Dor: esquece horários
ARTEFATO DCU: Mapa de Jornada → Etapa Pós-uso → Oportunidade: Notificação 24h
"""
from datetime import datetime, timedelta
from flask import Blueprint, jsonify
from app.models import Consulta, db

notificacoes_bp = Blueprint('notificacoes', __name__)

@notificacoes_bp.route('/api/lembretes/pendentes', methods=['GET'])
def listar_lembretes_pendentes():
    """Retorna consultas que acontecerão nas próximas 24h."""
    agora = datetime.now()
    limite = agora + timedelta(hours=24)
    
    consultas_proximas = Consulta.query.filter(
        Consulta.data_hora >= agora,
        Consulta.data_hora <= limite,
        Consulta.status == 'confirmada'
    ).all()
    
    return jsonify([{
        'id': c.id,
        'medico': c.medico_nome,
        'especialidade': c.especialidade,
        'data_hora': c.data_hora.isoformat(),
        'mensagem': f'Amanhã às {c.data_hora.strftime("%H:%M")} — '
                    f'{c.especialidade} com Dr(a). {c.medico_nome}'
    } for c in consultas_proximas])
```

#### Passo 5 — No Backend (TypeScript/Express)

```typescript
// src/routes/lembretes.routes.ts — API de lembretes em TypeScript
import { Router, Request, Response } from 'express';
import { pool } from '../config/database';

const router = Router();

/**
 * GET /api/lembretes/pendentes
 * RASTREABILIDADE DCU: Persona Mariana → Dor "esquece horários"
 * Jornada → Pós-uso → Oportunidade: Notificação push 24h antes
 */
router.get('/pendentes', async (req: Request, res: Response) => {
  const resultado = await pool.query(`
    SELECT 
      a.id,
      d.nome AS medico,
      d.especialidade,
      a.data_hora,
      FORMAT('Amanhã às %s — %s com Dr(a). %s',
        TO_CHAR(a.data_hora, 'HH24:MI'),
        d.especialidade,
        d.nome
      ) AS mensagem
    FROM agendamentos a
    JOIN medicos d ON d.id = a.medico_id
    WHERE a.data_hora BETWEEN NOW() AND NOW() + INTERVAL '24 hours'
      AND a.status = 'confirmada'
    ORDER BY a.data_hora ASC
  `);

  res.json(resultado.rows);
});

export default router;
```

**Prática 3 — 5 Problemas:**

| # | Problema | Impacto | Solução |
|---|---------|---------|---------|
| 1 | Texto "esqueceu a senha?" com contraste insuficiente (#CCC sobre branco = ratio ~1.6:1) | Idosos e daltônicos não conseguem ler | Usar #6B7280 (ratio 4.6:1) ou sublinhado |
| 2 | Fonte 11px muito pequena | Difícil leitura em qualquer tela | Mínimo 14px para links, 16px para corpo |
| 3 | Botões de login social sem ícones | Usuário não reconhece rapidamente | Adicionar ícones do Facebook/Google |
| 4 | Sem indicação de campo obrigatório | Usuário não sabe o que é necessário | Adicionar asterisco (*) ou label "obrigatório" |
| 5 | Botão "ENTRAR" sem feedback de estado (hover, loading, disabled) | Usuário clica múltiplas vezes sem saber se funcionou | Adicionar estados visuais + loading spinner |

### 📝 Opção B: Abordagem Desplugada (Unplugged UX Design)

> **Requisito:** Apenas sala de aula + quadro + papel + canetas coloridas (opcionais: post-its, cartolina, revistas para recorte).

#### Atividades Desplugadas por Tema

---

**🔹 Semanas 1-3: Pesquisa de Usuário (Desplugada)**

**Atividade: "Entrevista ao Vivo"**

| Item | Detalhe |
|------|---------|
| **Duração** | 80 min |
| **Material** | Folha A4, caneta |
| **Dinâmica** | Duplas |

**Roteiro do Professor:**

```
1. PREPARAÇÃO (10 min):
   - Escrever no quadro o roteiro de entrevista (5 perguntas)
   - Explicar técnica de entrevista: "Pergunte POR QUE 3 vezes"

2. EXECUÇÃO (40 min):
   - Aluno A entrevista Aluno B (20 min)
   - Aluno B entrevista Aluno A (20 min)
   - Tema: "Como você marca consultas médicas?"

3. SÍNTESE (20 min):
   - Cada dupla sintetiza os dados em 3 insights
   - Escreve os insights em post-its/folhas

4. COMPARTILHAMENTO (10 min):
   - Cada dupla cola seus insights no quadro
   - Turma identifica padrões entre as respostas
```

**Guia do Aluno:**
```
📝 ENTREVISTA DE PESQUISA (Dupla)

Você é um pesquisador de UX. Entreviste seu colega com estas perguntas:
1. Quando foi a última vez que você precisou marcar uma consulta médica?
2. Como você fez? (telefone, app, pessoalmente?)
3. Qual foi a parte mais frustrante?
4. O que tornaria esse processo mais fácil?
5. Você confia em apps para dados de saúde? Por quê?

REGRAS:
- Anote TUDO que o colega disser (frases exatas)
- Não julgue nem sugira respostas
- Pergunte "por quê?" quando a resposta for curta

Ao final: escreva 3 INSIGHTS em frases curtas.
```

**🔹 Semanas 4-5: Persona e User Stories (Desplugada)**

**Atividade: "Persona em Cartolina"**

| Item | Detalhe |
|------|---------|
| **Duração** | 80 min |
| **Material** | Cartolina A3, canetas coloridas, revistas para recorte (foto), cola |
| **Dinâmica** | Grupos de 3-4 alunos |

**Roteiro do Professor:**

```
1. CONTEXTO (10 min):
   - Projetar/escrever no quadro o template da persona
   - Explicar que a persona deve ser baseada nos dados das entrevistas

2. CONSTRUÇÃO (40 min):
   - Cada grupo cria 1 persona em cartolina grande
   - Usar recorte de revista para "foto" da persona
   - Preencher: nome, idade, dores, objetivos, frase-chave

3. USER STORIES (20 min):
   - Cada grupo escreve 5 User Stories derivadas da persona
   - Formato: "Como [persona], quero [ação] para [benefício]"

4. GALERIA (10 min):
   - Colar cartolinas na parede
   - Turma faz "gallery walk" e vota na persona mais realista
```

**🔹 Semanas 7-9: Jornada e Wireframe (Desplugada)**

**Atividade: "Wireframe no Papel Quadriculado"**

| Item | Detalhe |
|------|---------|
| **Duração** | 80 min |
| **Material** | Papel quadriculado (ou A4 com moldura de celular desenhada), lápis, borracha |
| **Dinâmica** | Individual |

**Roteiro do Professor:**

```
1. TEMPLATE (5 min):
   - Desenhar no quadro um retângulo na proporção de celular (9:16)
   - Mostrar exemplo de wireframe: retângulos = botões, linhas = texto

2. JORNADA NO QUADRO (15 min):
   - Desenhar a jornada do usuário em 5 etapas no quadro
   - Cada etapa = 1 tela que o aluno vai desenhar

3. WIREFRAMING (45 min):
   - Cada aluno desenha 5 telas à mão:
     * Tela 1: Login
     * Tela 2: Home (buscar médico)
     * Tela 3: Perfil do médico
     * Tela 4: Escolher horário
     * Tela 5: Confirmação
   - Usar apenas cinza (sem cores!) — foco na ESTRUTURA

4. REVISÃO EM PARES (15 min):
   - Trocar desenhos com o colega ao lado
   - Colega tenta "navegar" pelo wireframe e anota dúvidas
   - Feedback: "Eu não entendi o que este botão faz"
```

**Guia do Aluno:**
```
✏️ WIREFRAME À MÃO (Individual)

REGRAS DO WIREFRAME:
- Use apenas RETÂNGULOS e LINHAS (sem desenhos bonitos!)
- Retângulo = botão ou imagem
- Linhas onduladas = texto
- X no retângulo = imagem/foto
- Cada tela deve ter: cabeçalho + conteúdo + ação principal

DESENHE 5 TELAS (uma por folha):
1. Login (email + senha + botão entrar)
2. Home (barra de busca + lista de médicos)
3. Perfil do Médico (foto + info + botão agendar)
4. Horários (calendário + slots de hora)
5. Confirmação (resumo + botão confirmar)

DEPOIS: Entregue ao colega e peça para ele "usar" seu wireframe.
Se ele se perder → você tem um problema de usabilidade!
```

**🔹 Semanas 15-17: Teste de Usabilidade (Desplugada)**

**Atividade: "Teste de Usabilidade com Protótipo de Papel"**

| Item | Detalhe |
|------|---------|
| **Duração** | 80 min |
| **Material** | Wireframes desenhados nas semanas anteriores |
| **Dinâmica** | Trios (1 moderador, 1 usuário, 1 observador) |

**Roteiro do Professor:**

```
1. PREPARAÇÃO (10 min):
   - Explicar os 3 papéis: Moderador, Usuário, Observador
   - Entregar roteiro de teste (5 tarefas)
   - Moderador NÃO pode ajudar!

2. RODADA 1 (20 min):
   - Aluno A = Moderador (lê as tarefas)
   - Aluno B = Usuário (tenta completar usando o wireframe em papel)
   - Aluno C = Observador (anota problemas encontrados)

3. RODADA 2 (20 min):
   - Troca de papéis: B=Moderador, C=Usuário, A=Observador

4. RODADA 3 (20 min):

5. SÍNTESE (10 min):
   - Cada trio lista os 3 principais problemas encontrados
```

### 📊 Opção C: Estudo de Caso e PBL (Problem-Based Learning)

> **Requisito:** Apenas sala de aula + quadro. Professor pode projetar slides se tiver datashow, mas não é obrigatório.

#### Estudo de Caso 1: "O Redesign do Nubank"

**Duração:** 80 min | **Dinâmica:** Grupos de 4-5 alunos

**Material impresso/projetado para os alunos:**

```
📋 CASO: O REDESIGN DO NUBANK (2019 → 2023)

CONTEXTO:
Em 2019, o app do Nubank tinha um design minimalista com fundo roxo 
e interface limpa. Em 2023, após pesquisa com milhões de usuários, 
o app foi redesenhado com:
- Cartões de atalho personalizados na home
- Área de "Descobrir" com educação financeira
- Modo escuro automático
- Navegação por gestos

DADOS DA PESQUISA DO NUBANK:
- 78% dos usuários queriam acessar Pix em menos de 2 toques
- 45% não encontravam a função "Limite disponível"
- 62% usavam o app apenas para ver saldo (subutilização)
- NPS subiu de 72 para 87 após o redesign

PERGUNTAS PARA ANÁLISE:
1. Quais DORES dos usuários motivaram o redesign?
2. Que artefatos de DCU o time provavelmente criou antes de redesenhar?
3. Como você mediria se o redesign foi bem-sucedido? (métricas)
4. Identifique 2 decisões que parecem baseadas em PERSONA.
5. Se você fosse UX do Nubank, o que AINDA melhoraria?
```

**Roteiro do Professor:**

```
1. APRESENTAÇÃO DO CASO (15 min):
   - Ler/projetar o caso para a turma
   - Contextualizar: "Vocês são consultores de UX contratados"

2. DISCUSSÃO EM GRUPO (30 min):
   - Cada grupo responde às 5 perguntas
   - Anota respostas em folha grande / cartolina

3. APRESENTAÇÃO (25 min):
   - Cada grupo apresenta (5 min cada)
   - Turma debate divergências

4. CONEXÃO COM O PROJETO (10 min):
   - "Como aplicar essas lições ao nosso AgendaPro?"
   - Cada grupo cita 1 lição aplicável
```
