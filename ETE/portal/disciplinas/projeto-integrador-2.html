🔍 O que é o Projeto Integrador II?

O PI2 conecta as disciplinas do Módulo 2 em uma aplicação web completa com API REST.

🔗 Disciplinas Integradas

  • Desenvolvimento Web — Frontend HTML/CSS/JS
  • Engenharia de Software — UML + Processos
  • Design Centrado no Usuário — UX/UI

Do protótipo Figma ao deploy funcional.

🎯 Objetivo

Desenvolver uma aplicação web full-stack com API REST em Node.js, frontend responsivo e documentação UML completa.

💡 O PI2 simula o fluxo real de uma equipe de desenvolvimento ágil.

⚙️ Metodologia: Kanban + Git Flow

📋 Kanban Board

  • Backlog — Todas as tarefas futuras
  • To Do — Sprint atual (máx 5 cards)
  • In Progress — Em desenvolvimento (máx 2 por pessoa)
  • Code Review — Aguardando revisão do colega
  • Done — Mergeado na main

Ferramenta: GitHub Projects

🌿 Git Flow

  • main — Produção (sempre estável)
  • develop — Integração contínua
  • feature/* — Uma branch por funcionalidade
  • hotfix/* — Correções urgentes

📝 Convenção de Commits

  • feat: nova funcionalidade
  • fix: correção de bug
  • docs: documentação
  • style: formatação (sem lógica)

💡 Dicas e Erros Comuns

✅ Faça

  • Comece pela API — o frontend depende dela
  • Use Postman/Insomnia para testar rotas
  • CSS Mobile-first (media queries depois)
  • Documente os endpoints no README
  • Faça deploy cedo (mesmo incompleto)
  • UML deve refletir o código REAL

❌ Evite

  • Frontend bonito com API quebrada
  • CORS não configurado (erro clássico!)
  • Senhas em texto plano no banco
  • Diagramas UML copiados da internet
  • Ignorar responsividade no mobile
  • Commit de node_modules/
💡 Dica: Teste a API ANTES de conectar o frontend. Use console.log no fetch para debugar.
