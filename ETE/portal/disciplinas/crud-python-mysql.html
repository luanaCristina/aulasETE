🎯 O que você vai construir

Uma API que cadastra alunos (nome, email, idade) em um banco MySQL e responde em JSON.

Por que fazer?

A maioria dos sistemas guarda dados em banco relacional. Aqui você liga os dois mundos: SQL no banco e Python na aplicação.

O que você entrega

  • Banco escola com a tabela alunos
  • API Flask com 5 rotas + 1 de boas-vindas
  • Validação dos dados recebidos
  • Tratamento de erros com código HTTP correto

Como saber se deu certo

Cada rota tem um teste com curl e um comando SELECT para provar que a tabela mudou. No fim, você compara com o repositório da professora.

💡Escreva o código antes de abrir o repositório. Ele está no último slide para conferir ou corrigir.

1. Leia

Parte 2

Validação e as rotas da API: motivo, construção, teste e conferência no banco

🛡 Função auxiliar — validar_dados_aluno()

Por que existe

Nunca confie no que chega do cliente. Sem validar, um cadastro sem nome ou com idade "abc" iria para o banco (ou derrubaria a rota com erro).

O que fazer

  • Receber o JSON (dados) e um flag exigir_todos
  • No cadastro: nome, email e idade obrigatórios
  • Se idade vier: inteiro maior que zero
  • Retornar None se está tudo certo, ou o texto do erro

Dica

Pythondef validar_dados_aluno(dados, exigir_todos=True): if not dados: return "Nenhum dado foi enviado." if exigir_todos: if not str(dados.get("nome", "")).strip(): return "O campo 'nome' é obrigatório." # ... email e idade ... if "idade" in dados: try: if int(dados["idade"]) <= 0: return "A 'idade' deve ser maior que zero." except (ValueError, TypeError): return "A 'idade' deve ser um número inteiro." return None
ℹ️exigir_todos=False serve ao PUT: na atualização o cliente pode mandar só o campo que quer mudar.

➕ Função 1 — POST /alunos · Cadastrar (CREATE)

Por que existe

Inclui um novo aluno na tabela. É a única forma de colocar dados no banco pela API.

O que fazer

  • Ler o JSON: request.get_json(silent=True)
  • Validar; se houver erro, responder 400
  • Executar INSERT com placeholders
  • commit() e responder 201 com o id novo (cursor.lastrowid)
  • finally: fechar cursor e conexão

Dica

Pythonsql = "INSERT INTO alunos (nome, email, idade) VALUES (%s, %s, %s)" cursor.execute(sql, (nome, email, idade)) conexao.commit() novo_id = cursor.lastrowid

Por que %s e não f-string?

Com %s o driver envia os valores separados do SQL. Com f-string, um nome como x'); DROP TABLE alunos;-- viraria comando: é a SQL Injection.

Por que commit()?

O INSERT só vale depois do commit. Sem ele a API responde 201, mas ao reiniciar a conexão a linha não existe.

📖 Função 2 — GET /alunos · Listar e buscar (READ)

Por que existe

Mostra os alunos cadastrados. O filtro ?nome= evita trazer tudo quando só se quer um aluno.

O que fazer

  • Ler o parâmetro: request.args.get("nome")
  • Se veio nome: WHERE nome LIKE %s com "%" + nome + "%"
  • Senão: SELECT *
  • Usar cursor(dictionary=True) para as linhas virem como dicionários
  • Responder {"total": n, "alunos": [...]}

Dica

Pythoncursor = conexao.cursor(dictionary=True) if nome_busca: sql = "SELECT * FROM alunos WHERE nome LIKE %s ORDER BY id" cursor.execute(sql, (f"%{nome_busca}%",)) else: cursor.execute("SELECT * FROM alunos ORDER BY id") alunos = cursor.fetchall()
💡Aqui a f-string é segura porque ela só monta o valor (%Ana%) que ainda vai como parâmetro. O SQL continua com %s.

🔎 Função 3 — GET /alunos/<id> · Buscar um aluno

Por que existe

Os outros recursos (editar, deletar, detalhes) partem de um aluno específico, identificado pelo id.

O que fazer

  • Rota com <int:id>: o Flask só aceita número
  • SELECT * FROM alunos WHERE id = %s
  • fetchone(): devolve uma linha ou None
  • Se None: 404 com mensagem

Dica

Python@app.route("/alunos/<int:id>", methods=["GET"]) def buscar_aluno(id): ... cursor.execute("SELECT * FROM alunos WHERE id = %s", (id,)) aluno = cursor.fetchone() if aluno is None: return jsonify({"erro": f"Aluno {id} não encontrado."}), 404
Terminalcurl -i http://localhost:5000/alunos/1 # 200 + {"aluno": {...}} curl -i http://localhost:5000/alunos/999 # 404 + {"erro": ...}
SQLSELECT * FROM alunos WHERE id = 1; -- mesmos dados da API

Por que (id,) com vírgula? O driver espera uma tupla; sem a vírgula, (id) é só um número entre parênteses.

🔄 Função 4 — PUT /alunos/<id> · Atualizar (UPDATE)

Por que existe

Corrige dados de um aluno que já existe (e-mail errado, idade incorreta).

O que fazer

  • Validar com exigir_todos=False
  • Buscar o aluno atual; se não existe, 404
  • Usar o valor novo se foi enviado, senão manter o atual: dados.get("nome", atual["nome"])
  • Executar UPDATE ... WHERE id = %s e commit()

Dica

Pythonsql = "UPDATE alunos SET nome=%s, email=%s, idade=%s WHERE id=%s" cursor.execute(sql, (novo_nome, novo_email, nova_idade, id)) conexao.commit()
⚠️Nunca esqueça o WHERE. UPDATE alunos SET idade = 20; sem WHERE altera todos os alunos da tabela.

🗑 Função 5 — DELETE /alunos/<id> · Deletar (DELETE)

Por que existe

Remove um cadastro que não deve mais existir. Verificar antes se o aluno existe permite responder 404 em vez de fingir que apagou.

O que fazer

  • SELECT id ... WHERE id = %s: se não existe, 404
  • DELETE FROM alunos WHERE id = %s
  • commit() e 200 com mensagem

Dica

Pythoncursor.execute("DELETE FROM alunos WHERE id = %s", (id,)) conexao.commit() return jsonify({"mensagem": f"Aluno {id} deletado!"}), 200
Terminalcurl -i -X DELETE http://localhost:5000/alunos/4 # 200 curl -i -X DELETE http://localhost:5000/alunos/4 # 404 (já foi apagado) curl -i http://localhost:5000/alunos/4 # 404
SQLSELECT * FROM alunos WHERE id = 4; -- 0 linhas
ℹ️O id apagado não é reutilizado: o próximo cadastro continua a sequência do AUTO_INCREMENT.

🧯 Padrão de cada rota: try / except / finally

Pythonconexao = None try: conexao = get_connection() cursor = conexao.cursor(dictionary=True) ... # SQL da rota except Error as e: return jsonify({"erro": f"Erro no banco de dados: {e}"}), 500 finally: if conexao is not None and conexao.is_connected(): cursor.close() conexao.close()

except

Se o banco cair, a API responde 500 em JSON em vez de uma página de erro.

finally

Roda sempre, com sucesso ou erro. Garante que a conexão fecha e o MySQL não acumula conexões abertas.

Teste: pare o MySQL (docker stop mysql-aula ou o serviço) e chame GET /alunos. Esperado: 500 com "erro". Religue e chame de novo: volta a funcionar.
