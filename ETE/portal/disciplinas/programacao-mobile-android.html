🧩 Componentes e JSX

Tudo no React Native é um componente — peças reutilizáveis de interface.

TSX // src/components/DoctorCard.tsx import { View, Text, Image, TouchableOpacity, StyleSheet } from 'react-native'; type Props = { nome: string; especialidade: string; foto: string; onPress: () => void; }; export function DoctorCard({ nome, especialidade, foto, onPress }: Props) { return ( <TouchableOpacity style={styles.card} onPress={onPress}> <Image source={{ uri: foto }} style={styles.avatar} /> <View> <Text style={styles.nome}>{nome}</Text> <Text style={styles.especialidade}>{especialidade}</Text> </View> </TouchableOpacity> ); } const styles = StyleSheet.create({ card: { flexDirection: 'row', padding: 16, gap: 12, backgroundColor: '#1E293B', borderRadius: 8 }, avatar: { width: 48, height: 48, borderRadius: 24 }, nome: { color: '#F8FAFC', fontSize: 16, fontWeight: '600' }, especialidade: { color: '#94A3B8', fontSize: 14 }, });

🔄 State e Props — Dados no React

📥 Props (de fora para dentro)

  • Dados passados pelo pai
  • Somente leitura (imutáveis)
  • Configuram o componente
  • Exemplo: <Card nome="Dr. João" />

🔄 State (interno do componente)

  • Dados que mudam ao longo do tempo
  • Controlados pelo próprio componente
  • Mudança causa re-render
  • Exemplo: const [count, setCount] = useState(0)
💡 Regra de ouro: Se o dado vem de fora → Props. Se o dado muda internamente → State. Se vários componentes precisam → Context.

📋 Listas e FlatList

FlatList é o componente padrão para listas performáticas no React Native.

TSX // screens/DoctorList.tsx import { FlatList, TextInput, View } from 'react-native'; import { useState } from 'react'; export function DoctorListScreen() { const [busca, setBusca] = useState(''); const [medicos, setMedicos] = useState(MOCK_DOCTORS); const filtrados = medicos.filter(m => m.nome.toLowerCase().includes(busca.toLowerCase()) ); return ( <View style={{ flex: 1, padding: 16 }}> <TextInput placeholder="Buscar médico..." value={busca} onChangeText={setBusca} style={styles.input} /> <FlatList data={filtrados} keyExtractor={(item) => item.id} renderItem={({ item }) => ( <DoctorCard {...item} onPress={() => nav.navigate('Detail', { id: item.id })} /> )} ListEmptyComponent={<Text>Nenhum médico encontrado</Text>} /> </View> ); }
💡 Performance: FlatList renderiza apenas itens visíveis. Use keyExtractor sempre!

🪝 Hooks e Context API

Gerenciamento de estado global sem bibliotecas externas.

TSX // contexts/AuthContext.tsx import { createContext, useContext, useEffect, useState } from 'react'; import { onAuthStateChanged, User } from 'firebase/auth'; import { auth } from '../config/firebase'; type AuthContextData = { user: User | null; loading: boolean; }; const AuthContext = createContext<AuthContextData>({} as AuthContextData); export function AuthProvider({ children }: { children: React.ReactNode }) { const [user, setUser] = useState<User | null>(null); const [loading, setLoading] = useState(true); useEffect(() => { return onAuthStateChanged(auth, (u) => { setUser(u); setLoading(false); }); }, []); return ( <AuthContext.Provider value={{ user, loading }}> {children} </AuthContext.Provider> ); } export const useAuth = () => useContext(AuthContext);

📦 Publicação — EAS Build

Gere o APK/AAB sem precisar do Android Studio instalado.

Bash # 1. Instalar EAS CLI npm install -g eas-cli # 2. Login na conta Expo eas login # 3. Configurar projeto eas build:configure # 4. Gerar APK (preview — direto no celular) eas build --platform android --profile preview # 5. Gerar AAB (produção — Google Play) eas build --platform android --profile production # 6. Baixar APK gerado # → Link aparece no terminal após build
💡 Dica: Use o perfil "preview" para gerar APK instalável diretamente. O "production" gera AAB para a Play Store.
