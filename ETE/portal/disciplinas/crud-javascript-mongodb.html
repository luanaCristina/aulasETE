ETE Pernambuco — Módulo 1 — Fundação

Node.js • Express • EJS • MongoDB • mongosh • curl

🎯 O que você vai construir

Um cadastro de pessoas (name + surname) com as quatro operações do CRUD, páginas HTML e dados guardados no MongoDB.

Por que fazer?

CRUD está em quase todo sistema: cadastro de alunos, produtos, pedidos. Quem domina as 4 operações consegue montar a base de qualquer aplicação.

O que você entrega

  • Servidor Express com 6 rotas
  • Conexão com o MongoDB
  • 3 páginas EJS (listar, novo, editar)
  • Registros visíveis no mongosh

Como saber se deu certo

Cada rota tem um teste (navegador ou curl) e um comando no banco para provar que o dado mudou. No fim, você compara com o repositório da professora.

💡Regra desta aula: escreva o código antes de olhar o repositório. Ele fica no último slide, para conferir ou corrigir.

🧭 Como usar esta aula

1. Leia

Cada função tem dois slides: motivo + o que fazer e depois como testar + comando no banco.

2. Escreva

Digite o código no seu server.js. Os slides mostram a dica principal, não a resposta completa.

3. Teste

Rode o servidor, execute o teste do slide e confirme o resultado esperado no mongosh.

4. Confira

No final, compare com o repositório. Se algo falhou, use o slide de erros comuns.

⚠️Reinicie o servidor (Ctrl+C e node server.js) sempre que alterar o server.js. Mudanças nas views .ejs só precisam de F5 no navegador.

🍃 Escolha onde o MongoDB vai rodar

Opção A — Atlas (nuvem, grátis)

  • Crie conta em mongodb.com/atlas e um cluster gratuito (M0)
  • Em Database Access, crie um usuário e senha
  • Em Network Access, libere seu IP
  • Em Connect → Drivers, copie a string e troque <password> pela senha
.envDATABASE_URL=mongodb+srv://USUARIO:SENHA@SEU-CLUSTER.mongodb.net/

Opção B — Docker (local)

Sobe um MongoDB no seu computador, sem conta nenhuma:

Terminaldocker run -d --name mongo-aula -p 27017:27017 mongo:7
.envDATABASE_URL=mongodb://localhost:27017
🔐A string do Atlas contém a sua senha. Ela vai só no .env, nunca no código e nunca no GitHub. Use a sua própria conta; não reaproveite credenciais de outra pessoa.

🔌 Passo 3 — Conectar ao banco e subir o servidor

server.jsconst express = require("express") const { MongoClient, ObjectId } = require("mongodb") const dotenv = require("dotenv") dotenv.config() const api = express() const client = new MongoClient(process.env.DATABASE_URL) let collection api.set("view engine", "ejs") api.use(express.urlencoded({ extended: true })) // ... suas 6 rotas entram aqui ... async function iniciar() { await client.connect() collection = client.db("pessoa").collection("crud") console.log("Conectado ao MongoDB") api.listen(3000, () => console.log("Servidor na porta 3000")) } iniciar().catch((erro) => console.error("Erro ao iniciar:", erro))

Por que conectar antes do listen? Assim nenhuma requisição chega antes de collection existir.

Parte 2

As 6 funções do servidor: motivo, como construir, como testar e o que conferir no banco

📖 Função 1 — GET /show · Listar (READ)

Por que existe

É a tela principal: mostra tudo o que está no banco. Também é como você enxerga se as outras operações funcionaram.

O que fazer

  • Buscar todos os documentos da coleção
  • Entregar a lista para a view show.ejs
  • Rota assíncrona: o banco responde depois

Dica

JavaScriptapi.get("/show", async (req, res) => { const crud = await collection.find().toArray() res.render("show.ejs", { crud }) })
ℹ️find() devolve um cursor (um "ponteiro" para os resultados). .toArray() carrega tudo em uma lista que o EJS consegue percorrer. await espera o banco responder.

📖 Função 1 — a view views/show.ejs e o teste

views/show.ejs

EJS<table border="1"> <tr><td>Nome</td><td>Sobrenome</td><td>Ação</td></tr> <% crud.forEach(function(details) { %> <tr> <td><%= details.name %></td> <td><%= details.surname %></td> <td> <a href="/edit/<%= details._id %>">Editar</a> - <a href="/delete/<%= details._id %>">Deletar</a> </td> </tr> <% }) %> </table> <a href="/index">Novo</a>

<% %> executa JavaScript (laço). <%= %> imprime o valor já escapado, o que protege contra HTML injetado.

Como testar

Terminalcurl http://localhost:3000/show

Ou abra http://localhost:3000/show no navegador. Esperado: tabela só com o cabeçalho (banco vazio).

No banco:

mongoshmongosh "mongodb://localhost:27017/pessoa" db.crud.find()

Vazio: []. Depois da Função 3, os registros aparecem nos dois lugares.

📝 Função 2 — GET /index · Formulário de cadastro

Por que existe

O usuário precisa de uma tela para digitar os dados. A rota só mostra o formulário; quem grava é a Função 3.

O que fazer

JavaScriptapi.get("/index", (req, res) => { res.render("index.ejs") })
views/index.ejs<form action="/show" method="POST"> <input type="text" name="name" placeholder="Nome"> <input type="text" name="surname" placeholder="Sobrenome"> <button type="submit">Salvar</button> </form>
⚠️O atributo name de cada input vira a chave em req.body. Se escrever name="nome" aqui e req.body.name no servidor, o valor chega undefined.

Teste: abra http://localhost:3000/index. Esperado: dois campos e um botão. Banco: nada muda (rota só de leitura).

➕ Função 3 — POST /show · Criar (CREATE)

Por que existe

Recebe os dados do formulário e grava no MongoDB. Sem ela, o banco nunca ganha dados.

O que fazer

  • Ler req.body.name e req.body.surname
  • Inserir um documento na coleção
  • Redirecionar para /show

Dica

JavaScriptapi.post("/show", async (req, res) => { await collection.insertOne({ name: req.body.name, surname: req.body.surname, }) res.redirect("/show") })
ℹ️Por que redirect e não render? Se a resposta fosse a própria página, apertar F5 reenviaria o formulário e duplicaria o registro. O redirecionamento troca o POST por um GET /show seguro.

O express.urlencoded do Passo 3 é o que transforma o corpo do formulário em req.body.

➕ Função 3 — teste e conferência no banco

Teste pelo navegador

  • Abra /index
  • Digite Ana e Silva e clique em Salvar
  • Esperado: volta para /show com a Ana na tabela

Teste pelo terminal

Terminalcurl -i -X POST http://localhost:3000/show \ -d "name=Bruno" -d "surname=Lima"

Esperado: HTTP/1.1 302 Found e Location: /show. O 302 é o redirecionamento.

Conferir no banco:

mongoshdb.crud.find() db.crud.countDocuments() // deve ser 2

Cada documento ganhou um _id automático do tipo ObjectId (você não o criou).

✏️ Função 4 — GET /edit/:id · Abrir a edição

Por que existe

Antes de alterar, o usuário precisa ver os dados atuais do registro dentro de um formulário preenchido.

O que fazer

  • Ler o :id da URL (req.params.id)
  • Buscar esse documento
  • Renderizar edit.ejs com os valores

Dica

JavaScriptapi.get("/edit/:id", async (req, res) => { const crud = await collection .find({ _id: new ObjectId(req.params.id) }) .toArray() res.render("edit.ejs", { crud }) })
⚠️Por que new ObjectId(...)? No banco, o _id não é texto: é um ObjectId. Comparar com a string da URL nunca encontra nada. Esse é o erro mais comum do CRUD com MongoDB.

✏️ Função 4 — a view views/edit.ejs e o teste

views/edit.ejs

EJS<% crud.forEach(function(details) { %> <form action="/edit/<%= details._id %>" method="POST"> <input type="text" name="name" value="<%= details.name %>"> <input type="text" name="surname" value="<%= details.surname %>"> <a href="/show">Todos</a> <button type="submit">Editar</button> </form> <% }) %>

Como testar

  • Em /show, clique em Editar na Ana
  • Esperado: formulário já com Ana e Silva
Terminalcurl http://localhost:3000/edit/COLE_O_ID_AQUI

Pegue o id no mongosh: db.crud.find({}, {_id: 1, name: 1}).

No banco: nada muda (só leitura).

🔄 Função 5 — POST /edit/:id · Atualizar (UPDATE)

Por que existe

Grava no banco as alterações feitas no formulário da Função 4.

O que fazer

  • Localizar o documento pelo _id
  • Trocar name e surname
  • Redirecionar para /show

Dica

JavaScriptapi.post("/edit/:id", async (req, res) => { await collection.updateOne( { _id: new ObjectId(req.params.id) }, { $set: { name: req.body.name, surname: req.body.surname, } } ) res.redirect("/show") })
ℹ️Dois argumentos: o filtro (qual documento) e a mudança. O $set altera só os campos listados e preserva o resto do documento.

🔄 Função 5 — teste e conferência no banco

Teste pelo navegador

  • Edite a Ana para Ana Maria
  • Clique em Editar
  • Esperado: /show mostra "Ana Maria"

Teste pelo terminal

Terminalcurl -i -X POST http://localhost:3000/edit/COLE_O_ID_AQUI \ -d "name=Ana Maria" -d "surname=Silva"

Esperado: 302 Found com Location: /show.

Conferir no banco:

mongoshdb.crud.find({ name: "Ana Maria" }) db.crud.countDocuments() // continua 2: atualizar NÃO cria registro
✅O _id da Ana é o mesmo de antes. Se o número de documentos aumentou, você criou em vez de atualizar.

🗑 Função 6 — GET /delete/:id · Deletar (DELETE)

Por que existe

Remove um registro que não é mais necessário (cadastro errado, duplicado).

O que fazer

JavaScriptapi.get("/delete/:id", async (req, res) => { await collection.deleteOne({ _id: new ObjectId(req.params.id), }) res.redirect("/show") })

Teste

  • Em /show, clique em Deletar no Bruno
  • Esperado: ele some da tabela
Terminalcurl -i http://localhost:3000/delete/COLE_O_ID_AQUI

Esperado: 302 Found.

Conferir no banco

mongoshdb.crud.find({ name: "Bruno" }) // [] db.crud.countDocuments() // 1
⚠️Deletar com GET é perigoso em sistemas reais: um link ou um robô de busca pode apagar dados. Aqui é só para estudo; em API de verdade use DELETE e peça confirmação.

Parte 3

Comandos do banco para você praticar sozinho(a)

🍃 Comandos do mongosh que você vai usar

mongoshmongosh "mongodb://localhost:27017" # entrar (Atlas: use a string do Atlas) show dbs // lista os bancos use pessoa // escolhe (ou prepara) o banco "pessoa" show collections // lista as coleções do banco atual db.crud.find() // todos os documentos db.crud.find({ name: "Ana" }) // com filtro db.crud.countDocuments() // quantos existem

Alterar (conferir a Função 5 e 6)

mongoshdb.crud.updateOne( { name: "Ana" }, { $set: { surname: "Souza" } } ) db.crud.deleteOne({ name: "Ana" })

Cuidado

mongoshdb.crud.deleteMany({}) // apaga TODOS db.crud.drop() // apaga a coleção

Use para limpar o ambiente de estudo. Nunca em um banco que não seja o seu.

ℹ️O banco pessoa e a coleção crud só passam a existir quando você grava o primeiro documento. Não precisa criá-los antes.

1. Compare arquivos

  • Há await nas chamadas ao banco?
