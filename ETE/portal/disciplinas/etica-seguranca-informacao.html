⚖️ LGPD na Prática — Para Desenvolvedores

Lei Geral de Proteção de Dados (Lei 13.709/2018) — o que muda no seu código.

📋 Princípios da LGPD

  • Finalidade: Coletar só o necessário
  • Consentimento: Usuário deve autorizar
  • Transparência: Informar o que coleta
  • Segurança: Proteger dados armazenados
  • Eliminação: Deletar quando solicitado

💻 Na Prática (AgendaPro)

  • ✅ Tela de consentimento no cadastro
  • ✅ Endpoint "deletar minha conta"
  • ✅ Criptografar dados sensíveis (CPF, saúde)
  • ✅ Log de acesso a dados pessoais
  • ✅ Política de privacidade acessível
  • ❌ Não compartilhar dados sem consentimento
⚠️ Multa: Até 2% do faturamento (máximo R$ 50 milhões por infração). Dados de saúde são considerados "sensíveis" pela LGPD.

🔐 Criptografia — Simétrica vs. Assimétrica

🔑 Simétrica (AES)

  • Mesma chave para criptografar e descriptografar
  • Rápida e eficiente
  • Problema: como compartilhar a chave?
  • Uso: dados em repouso (banco de dados)

Analogia: cadeado com cópia da chave

🔑🔑 Assimétrica (RSA)

  • Par de chaves: pública + privada
  • Pública encripta, privada decripta
  • Mais lenta, mas resolve compartilhamento
  • Uso: HTTPS, JWT, assinaturas digitais

Analogia: caixa de correio (todos colocam, só dono abre)

🎯 Na prática: HTTPS = assimétrica (handshake) + simétrica (dados). Senhas = hash (bcrypt) — NÃO é criptografia, é irreversível!

🎫 Autenticação e JWT

JSON Web Tokens — o padrão para autenticação stateless em APIs.

Estrutura JWT // JWT = Header.Payload.Signature // HEADER (algoritmo) { "alg": "HS256", "typ": "JWT" } // PAYLOAD (dados do usuário) { "sub": "uid123", "name": "Maria Silva", "role": "patient", "iat": 1719849600, // emitido em "exp": 1719936000 // expira em (24h depois) } // SIGNATURE (verificação) HMACSHA256(base64(header) + "." + base64(payload), SECRET_KEY) // Token final: eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ1aWQxMjMi... // ⚠️ Payload é apenas codificado (base64), NÃO criptografado!
⚠️ Regras: Sempre definir expiração (exp). Nunca colocar dados sensíveis no payload. Armazenar token de forma segura (httpOnly cookie ou SecureStore no mobile).

🔍 Auditoria de Código — Vulnerável vs. Seguro

Compare: código com falhas de segurança vs. código corrigido

Python — VULNERÁVEL # ❌ SQL INJECTION — NUNCA faça isso! @app.route('/login', methods=['POST']) def login(): username = request.form['username'] password = request.form['password'] # String concatenation = SQL Injection! query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'" user = db.execute(query).fetchone() # Input: username = ' OR '1'='1' -- # Resultado: acesso sem senha! 💀
Python — SEGURO # ✅ PARAMETERIZED QUERY + HASH from werkzeug.security import check_password_hash @app.route('/login', methods=['POST']) def login(): username = request.form['username'] password = request.form['password'] # Query parametrizada (imune a injection) user = db.execute( "SELECT * FROM users WHERE username = ?", (username,) ).fetchone() # Verificar hash da senha (bcrypt) if user and check_password_hash(user['password_hash'], password): token = create_jwt(user['id']) return jsonify({'token': token}) return jsonify({'error': 'Credenciais inválidas'}), 401
TypeScript — VULNERÁVEL // ❌ BROKEN ACCESS CONTROL app.get('/api/appointments/:id', async (req, res) => { const { id } = req.params; // Qualquer usuário acessa qualquer agendamento! const appointment = await db.query( 'SELECT * FROM appointments WHERE id = $1', [id] ); // Sem verificar se pertence ao usuário logado 💀 res.json(appointment.rows[0]); }); // Atacante: GET /api/appointments/999 → vê dados de outro paciente!
TypeScript — SEGURO // ✅ ACCESS CONTROL + OWNERSHIP CHECK app.get('/api/appointments/:id', authMiddleware, async (req, res) => { const { id } = req.params; const userId = req.user.uid; // do JWT verificado const appointment = await db.query( 'SELECT * FROM appointments WHERE id = $1 AND patient_id = $2', [id, userId] // Filtra pelo dono! ); if (!appointment.rows[0]) { return res.status(404).json({ error: 'Não encontrado' }); } res.json(appointment.rows[0]); }); // Atacante: GET /api/appointments/999 → 404 (não é dele)

✅ Checklist de Segurança — Para Todo Projeto

🔐 Autenticação

  • ☐ Senhas com hash (bcrypt, 12+ rounds)
  • ☐ JWT com expiração (max 24h)
  • ☐ Rate limiting no login (5 tentativas)
  • ☐ 2FA disponível (opcional para usuário)

🛡️ Dados

  • ☐ HTTPS em toda comunicação
  • ☐ Dados sensíveis criptografados
  • ☐ Backup automático + teste de restore
  • ☐ Logs de acesso a dados pessoais

💻 Código

  • ☐ Input validation (Zod, Yup)
  • ☐ Queries parametrizadas (nunca concatenar)
  • ☐ Dependências atualizadas (npm audit)
  • ☐ Variáveis de ambiente (.env, não hardcoded)

📱 Mobile

  • ☐ Token em SecureStore (não AsyncStorage)
  • ☐ Certificate pinning (APIs críticas)
  • ☐ Ofuscação de código (produção)
  • ☐ Sem dados sensíveis em logs
