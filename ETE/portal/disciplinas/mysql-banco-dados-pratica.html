O SGBD protege relações, evita duplicidades, atende mais de uma pessoa e permite permissões, backup e consultas complexas.

🔑 Chaves dão identidade e conectam tabelas

Chave primária (PK)

É o identificador único de uma linha. Em geral, usamos um número criado automaticamente.

SQLid INT AUTO_INCREMENT PRIMARY KEY

Chave estrangeira (FK)

Guarda o id de outra tabela. Ela impede empréstimo para aluno inexistente e cria a relação entre os dados.

SQLaluno_id INT NOT NULL, FOREIGN KEY (aluno_id) REFERENCES alunos(id)
📌Relação 1:N: um aluno pode realizar muitos empréstimos; cada empréstimo pertence a um aluno.

📐 Um banco começa pela pergunta certa

Requisitos da biblioteca

  1. Cadastrar aluno com nome, turma e e-mail único.
  2. Cadastrar livro com título, autor e quantidade disponível.
  3. Registrar quem pegou qual livro e a data.
  4. Listar atrasos e os livros mais emprestados.

🏗️ Crie tabelas com regras desde o início

SQLCREATE TABLE alunos ( id INT AUTO_INCREMENT PRIMARY KEY, nome VARCHAR(100) NOT NULL, turma VARCHAR(20) NOT NULL, email VARCHAR(150) NOT NULL UNIQUE, ativo BOOLEAN NOT NULL DEFAULT TRUE, criado_em TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ); CREATE TABLE livros ( id INT AUTO_INCREMENT PRIMARY KEY, titulo VARCHAR(180) NOT NULL, autor VARCHAR(120) NOT NULL, estoque INT NOT NULL DEFAULT 0, CHECK (estoque >= 0) );

O nome de cada regra comunica intenção: NOT NULL torna obrigatório, UNIQUE evita repetição e DEFAULT cria um valor inicial coerente.

🔗 Emprestimos conectam alunos e livros

SQLCREATE TABLE emprestimos ( id INT AUTO_INCREMENT PRIMARY KEY, aluno_id INT NOT NULL, livro_id INT NOT NULL, retirado_em DATE NOT NULL, previsto_para DATE NOT NULL, devolvido_em DATE NULL, CONSTRAINT fk_emprestimo_aluno FOREIGN KEY (aluno_id) REFERENCES alunos(id), CONSTRAINT fk_emprestimo_livro FOREIGN KEY (livro_id) REFERENCES livros(id), CHECK (previsto_para >= retirado_em) );
💡Crie primeiro as tabelas que serão referenciadas. Depois crie a tabela que contém as FKs.

➕ INSERT: cada coluna recebe um valor explícito

Insira vários alunos

SQLINSERT INTO alunos (nome, turma, email) VALUES ('Ana Souza', 'DS 2026.2', 'ana@ete.edu.br'), ('Caio Lima', 'DS 2026.2', 'caio@ete.edu.br'), ('Bia Alves', 'DS 2026.1', 'bia@ete.edu.br');

Insira livros

SQLINSERT INTO livros (titulo, autor, estoque) VALUES ('O Cortiço', 'Aluísio Azevedo', 3), ('Capitães da Areia', 'Jorge Amado', 2); SELECT LAST_INSERT_ID();

Liste sempre as colunas: fica claro o que está sendo salvo e a ordem deixa de ser um risco.

🔎 SELECT transforma perguntas em resultados

SQL-- Quais alunos ativos são da turma DS 2026.2? SELECT id, nome, email FROM alunos WHERE turma = 'DS 2026.2' AND ativo = TRUE ORDER BY nome ASC; -- Quais livros têm pelo menos duas cópias? SELECT titulo, autor, estoque FROM livros WHERE estoque >= 2 ORDER BY estoque DESC, titulo; -- Paginação simples SELECT id, titulo FROM livros LIMIT 5 OFFSET 0;

Ordem de leitura: FROM → WHERE → SELECT → ORDER BY → LIMIT. Nem sempre é a mesma ordem em que escrevemos.

🎯 WHERE filtra antes de mostrar

ObjetivoCondição
Buscar parte de um nomenome LIKE 'Ana%'

⚠️= NULL não funciona. Ausência de valor é consultada com IS NULL ou IS NOT NULL.

📊 Agrupe para responder perguntas de gestão

Funções agregadoras

COUNT(*)quantidade de linhas
SUM()soma de valores
AVG()média
MIN() / MAX()menor / maior

Livros mais procurados

SQLSELECT livro_id, COUNT(*) AS total FROM emprestimos GROUP BY livro_id HAVING COUNT(*) >= 2 ORDER BY total DESC;

WHERE filtra linhas antes do grupo. HAVING filtra grupos depois da contagem.

🤝 JOIN reúne dados que foram modelados separados

SQLSELECT e.id, a.nome AS aluno, l.titulo AS livro, e.retirado_em, e.previsto_para FROM emprestimos e INNER JOIN alunos a ON a.id = e.aluno_id INNER JOIN livros l ON l.id = e.livro_id WHERE e.devolvido_em IS NULL ORDER BY e.previsto_para;

INNER JOIN

Retorna apenas relações que existem dos dois lados.

LEFT JOIN

Mantém toda a tabela da esquerda, mesmo quando não há par do outro lado.

✏️ UPDATE altera somente o que você confirma

Passo seguro

  1. Faça um SELECT com o mesmo WHERE.
  2. Confira a quantidade e os ids retornados.
  3. Execute o UPDATE.
  4. Consulte novamente para verificar.

Exemplo: devolver livro

SQLSELECT * FROM emprestimos WHERE id = 3; UPDATE emprestimos SET devolvido_em = CURRENT_DATE WHERE id = 3; SELECT id, devolvido_em FROM emprestimos WHERE id = 3;

🗑️ DELETE exige uma condição inequívoca

Apague uma linha

SQL-- Primeiro confirme SELECT * FROM alunos WHERE id = 9; -- Depois remova só esse registro DELETE FROM alunos WHERE id = 9;

Sem WHERE, um DELETE alcança todas as linhas. Pare e revise antes de executar.

Transação: tudo ou nada

SQLSTART TRANSACTION; UPDATE livros SET estoque = estoque - 1 WHERE id = 2 AND estoque > 0; INSERT INTO emprestimos (...) VALUES (...); COMMIT; -- confirma -- ROLLBACK; -- desfaz se algo falhar

⚡ Índices aceleram; views simplificam

Índice

SQLCREATE INDEX idx_emprestimos_aluno ON emprestimos (aluno_id); EXPLAIN SELECT * FROM emprestimos WHERE aluno_id = 2;

Crie índice para campos muito filtrados ou usados em JOIN; índices demais também custam espaço e escrita.

View

SQLCREATE VIEW vw_emprestimos_abertos AS SELECT a.nome, l.titulo, e.previsto_para FROM emprestimos e JOIN alunos a ON a.id = e.aluno_id JOIN livros l ON l.id = e.livro_id WHERE e.devolvido_em IS NULL; SELECT * FROM vw_emprestimos_abertos;

⚙️ Trigger automatiza uma regra do banco

Problema

Ao registrar um empréstimo, o estoque precisa diminuir. Ao registrar a devolução, o estoque precisa aumentar.

Uma trigger é acionada por um evento, como INSERT ou UPDATE.

Exemplo didático

SQLDELIMITER // CREATE TRIGGER tr_baixa_estoque AFTER INSERT ON emprestimos FOR EACH ROW BEGIN UPDATE livros SET estoque = estoque - 1 WHERE id = NEW.livro_id AND estoque > 0; END// DELIMITER ;
⚠️Triggers escondem lógica da aplicação. Use-as para regras pequenas, documente-as e teste antes de adotá-las em projetos reais.

🛡️ Banco seguro não usa root na aplicação

Usuário da aplicação

SQLCREATE USER 'app_biblioteca'@'localhost' IDENTIFIED BY 'senha-forte-unica'; GRANT SELECT, INSERT, UPDATE, DELETE ON biblioteca_ete.* TO 'app_biblioteca'@'localhost'; FLUSH PRIVILEGES;

Backup e restauração

Terminalmysqldump -u root -p biblioteca_ete \ > biblioteca_ete.sql mysql -u root -p biblioteca_ete \ < biblioteca_ete.sql

Senha e arquivos de backup não pertencem a commits públicos.

📝 Exercício 1 — Banco da cantina

Situação

A cantina vende produtos e registra pedidos. Um pedido pertence a um aluno e pode conter vários produtos.

Sua tarefa

  1. Liste três entidades e os campos mínimos.
  2. Defina as PKs e FKs.
  3. Escreva CREATE TABLE para alunos, produtos e pedidos.

Critérios

  • Nome de aluno e produto não podem ficar vazios.
  • Preço deve usar DECIMAL(10,2).
  • Quantidade deve ser positiva.
  • Pedido deve apontar para aluno existente.

Tempo sugerido: 20 minutos em dupla.

✅ Gabarito 1 — Modelo mínimo da cantina

SQLCREATE TABLE alunos ( id INT AUTO_INCREMENT PRIMARY KEY, nome VARCHAR(100) NOT NULL ); CREATE TABLE produtos ( id INT AUTO_INCREMENT PRIMARY KEY, nome VARCHAR(100) NOT NULL, preco DECIMAL(10,2) NOT NULL, CHECK (preco >= 0) ); CREATE TABLE pedidos ( id INT AUTO_INCREMENT PRIMARY KEY, aluno_id INT NOT NULL, produto_id INT NOT NULL, quantidade INT NOT NULL, FOREIGN KEY (aluno_id) REFERENCES alunos(id), FOREIGN KEY (produto_id) REFERENCES produtos(id), CHECK (quantidade > 0) );

Em uma versão mais completa, pedido e item_pedido seriam tabelas separadas. Este gabarito prioriza o conceito de relacionamento.

📝 Exercício 2 — Consulta e atualização

Comandos solicitados

  1. Cadastre três produtos.
  2. Liste apenas itens com preço menor que R$ 10,00.
  3. Aumente o preço de um produto em 10%.
  4. Remova um produto específico com segurança.

Regra de ouro

Antes de qualquer UPDATE ou DELETE, escreva um SELECT com o mesmo WHERE.

🔍Se o SELECT retornar mais linhas do que o esperado, não execute a alteração ainda.

✅ Gabarito 2 — CRUD com segurança

SQLINSERT INTO produtos (nome, preco) VALUES ('Suco', 6.50), ('Sanduíche', 9.00), ('Bolo', 8.50); SELECT id, nome, preco FROM produtos WHERE preco < 10.00 ORDER BY preco; SELECT * FROM produtos WHERE nome = 'Suco'; UPDATE produtos SET preco = preco * 1.10 WHERE nome = 'Suco'; SELECT * FROM produtos WHERE nome = 'Bolo'; DELETE FROM produtos WHERE nome = 'Bolo';

📝 Exercício 3 — Relatório de empréstimos

Usando alunos, livros e emprestimos, responda:

Parte A: detalhamento

Liste nome do aluno, título do livro, data de retirada e data prevista apenas para empréstimos ainda abertos.

Parte B: resumo

Conte quantos empréstimos cada aluno realizou. Mostre somente alunos com dois ou mais empréstimos.

Desafio

Use LEFT JOIN para listar todos os alunos, inclusive quem ainda não fez empréstimo.

✅ Gabarito 3 — Relatório com JOIN e GROUP BY

SQLSELECT a.nome, l.titulo, e.retirado_em, e.previsto_para FROM emprestimos e JOIN alunos a ON a.id = e.aluno_id JOIN livros l ON l.id = e.livro_id WHERE e.devolvido_em IS NULL; SELECT a.nome, COUNT(e.id) AS total_emprestimos FROM alunos a LEFT JOIN emprestimos e ON e.aluno_id = a.id GROUP BY a.id, a.nome HAVING COUNT(e.id) >= 2 ORDER BY total_emprestimos DESC;
