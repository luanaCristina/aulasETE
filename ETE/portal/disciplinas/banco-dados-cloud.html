🔍 SQL vs. NoSQL — Quando Usar Cada Um?

EstruturaTabelas com schema fixoDocumentos/Coleções flexíveis
RelaçõesJOINs entre tabelasDados desnormalizados/embutidos
EscalaVertical (mais hardware)Horizontal (mais servidores)
ConsultasSQL poderoso e flexívelQueries limitadas, mas rápidas
Ideal paraTransações financeiras, relatóriosApps real-time, mobile, IoT
ExemploSistema bancário, ERPChat, rede social, AgendaPro

📝 Firestore — CRUD Completo

As 4 operações fundamentais em qualquer banco de dados.

TypeScript import { collection, addDoc, getDocs, updateDoc, deleteDoc, doc } from 'firebase/firestore'; import { db } from '../config/firebase'; // CREATE — Adicionar documento const criar = async () => { await addDoc(collection(db, 'appointments'), { patientId: 'uid123', doctorName: 'Dr. João', date: '2026-08-15', time: '14:00', status: 'confirmed' }); }; // READ — Buscar todos os documentos const listar = async () => { const snap = await getDocs(collection(db, 'appointments')); return snap.docs.map(d => ({ id: d.id, ...d.data() })); }; // UPDATE — Atualizar campo específico const atualizar = async (id: string) => { await updateDoc(doc(db, 'appointments', id), { status: 'cancelled' }); }; // DELETE — Remover documento const remover = async (id: string) => { await deleteDoc(doc(db, 'appointments', id)); };

🔒 Security Rules — Protegendo seus Dados

Rules definem QUEM pode ler/escrever QUAIS dados.

Firestore Rules rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { // Usuários: só lê/escreve seu próprio perfil match /users/{userId} { allow read, write: if request.auth != null && request.auth.uid == userId; } // Agendamentos: paciente lê os seus, médico lê os dele match /appointments/{appointmentId} { allow read: if request.auth != null && (resource.data.patientId == request.auth.uid || resource.data.doctorId == request.auth.uid); allow create: if request.auth != null && request.resource.data.patientId == request.auth.uid; allow update: if request.auth != null && resource.data.patientId == request.auth.uid; allow delete: if false; // Ninguém deleta — só cancela } } }
⚠️ NUNCA use allow read, write: if true em produção! Sempre valide autenticação e propriedade.

Mesmo CRUD, 3 formas de acessar o Firestore

TypeScript // Frontend/Mobile — Firebase JS SDK v9+ import { collection, addDoc, serverTimestamp } from 'firebase/firestore'; const criarAgendamento = async (data: AppointmentData) => { const docRef = await addDoc(collection(db, 'appointments'), { ...data, createdAt: serverTimestamp(), status: 'confirmed' }); console.log('Criado com ID:', docRef.id); };
Python # Backend/Scripts — Firebase Admin SDK (Python) import firebase_admin from firebase_admin import credentials, firestore cred = credentials.Certificate('service-account.json') firebase_admin.initialize_app(cred) db = firestore.client() def criar_agendamento(data: dict): doc_ref = db.collection('appointments').add({ **data, 'createdAt': firestore.SERVER_TIMESTAMP, 'status': 'confirmed' }) print(f'Criado com ID: {doc_ref[1].id}')

🔐 Firebase Auth + Storage

🔑 Authentication

  • Email/Senha — Cadastro padrão
  • Google Sign-In — OAuth 2.0
  • Anônimo — Sem cadastro
  • Telefone — SMS (SMS custa)

onAuthStateChanged() → listener global

📁 Cloud Storage

  • Upload de imagens (perfil, documentos)
  • Gera URL pública ou privada
  • Rules de acesso por usuário
  • Limites: tipo, tamanho, caminho

Caminho: /users/{uid}/avatar.jpg

💡 Pattern: Auth fornece o UID → Use UID como chave para organizar dados no Firestore e Storage.
