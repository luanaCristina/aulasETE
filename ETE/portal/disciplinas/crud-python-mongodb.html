Flask, PyMongo e testes de cada rota — para fazer sozinho(a)

ETE Pernambuco — Módulo 1 — Fundação

Python • Flask • Jinja2 • PyMongo • MongoDB • mongosh • curl

🎯 O que você vai construir

O mesmo cadastro de pessoas (name + surname) da aula de JavaScript, agora em Python, gravando no mesmo MongoDB.

Por que fazer?

Refazer a mesma solução em outra linguagem mostra o que é conceito (CRUD, rotas, banco) e o que é só sintaxe (Express × Flask, EJS × Jinja2).

O que você entrega

  • Servidor Flask com 6 rotas
  • Conexão com o MongoDB via PyMongo
  • 3 templates Jinja2 (listar, novo, editar)
  • Registros visíveis no mongosh

Como saber se deu certo

Cada rota tem teste (navegador ou curl) e um comando no banco. No fim, compare com a pasta api-python do repositório da professora.

💡Fez a aula de JavaScript? Ótimo: as rotas são as mesmas. Se não fez, não tem problema: tudo é explicado aqui.

🧭 Como usar esta aula

1. Leia

Cada função tem dois slides: motivo + o que fazer e teste + comando no banco.

2. Escreva

Digite no seu app.py. Os slides mostram a dica principal, não a resposta completa.

3. Teste

Rode python app.py, faça o teste do slide e veja o resultado no mongosh.

4. Confira

No final, compare com o repositório. Em caso de erro, veja o slide de erros comuns.

ℹ️Com debug=True o Flask reinicia sozinho ao salvar o app.py. Templates .html também atualizam com F5.

🔌 Passo 3 — Conectar e subir o servidor

app.pyimport os from bson.objectid import ObjectId from dotenv import load_dotenv from flask import Flask, redirect, render_template, request from pymongo import MongoClient load_dotenv() app = Flask(__name__) client = MongoClient(os.getenv("DATABASE_URL")) collection = client["pessoa"]["crud"] # ... suas 6 rotas entram aqui ... if __name__ == "__main__": client.admin.command("ping") print("Conectado ao MongoDB") app.run(port=3002, debug=True)

Por que o ping? O PyMongo conecta de forma "preguiçosa": sem o ping, você só descobriria um erro de conexão na primeira rota. O ping falha logo na inicialização.

Se não funcionou

  • Authentication failed: usuário ou senha da URL
  • ModuleNotFoundError: venv desativado; ative e rode o pip install

As 6 funções: motivo, construção, teste e conferência no banco

📖 Função 1 — GET /show · Listar (READ)

Por que existe

É a tela principal e a forma de enxergar se as demais operações funcionaram.

O que fazer

  • Buscar todos os documentos
  • Converter o cursor em lista
  • Enviar a lista ao template show.html

Dica

Python@app.route("/show", methods=["GET"]) def listar(): pessoas = list(collection.find()) return render_template("show.html", pessoas=pessoas)
ℹ️find() devolve um cursor (leitura sob demanda). list(...) carrega tudo para o Jinja2 percorrer.

📖 Função 1 — templates/show.html e teste

templates/show.html

Jinja2<table border="1"> <tr><td>Nome</td><td>Sobrenome</td><td>Ação</td></tr> {% for p in pessoas %} <tr> <td>{{ p.name }}</td> <td>{{ p.surname }}</td> <td> <a href="/edit/{{ p._id }}">Editar</a> - <a href="/delete/{{ p._id }}">Deletar</a> </td> </tr> {% endfor %} </table> <a href="/index">Novo</a>

📝 Função 2 — GET /index · Formulário

Por que existe

O usuário precisa de uma tela para digitar. Esta rota só mostra o formulário; quem grava é a Função 3.

O que fazer

Python@app.route("/index") def formulario(): return render_template("index.html")
templates/index.html<form action="/show" method="POST"> <input type="text" name="name" placeholder="Nome"> <input type="text" name="surname" placeholder="Sobrenome"> <button type="submit">Salvar</button> </form>
⚠️O atributo name do input é a chave em request.form. Se não bater, o Flask responde 400 Bad Request (KeyError/chave ausente).

Teste: abra http://localhost:3002/index. Banco: nada muda.

➕ Função 3 — POST /show · Criar (CREATE)

Por que existe

Recebe o formulário e grava no MongoDB.

O que fazer

  • Declarar a rota com methods=["POST"]
  • Ler request.form["name"] e ["surname"]
  • Inserir o documento
  • Redirecionar para /show

Dica

Python@app.route("/show", methods=["POST"]) def criar(): collection.insert_one({ "name": request.form["name"], "surname": request.form["surname"], }) return redirect("/show")
ℹ️Por que redirect? Se a resposta fosse a página, F5 reenviaria o formulário e duplicaria o registro. O redirecionamento transforma o POST em um GET /show seguro.

As rotas GET /show e POST /show têm o mesmo caminho, mas funções diferentes: o methods separa uma da outra.

✏️ Função 4 — GET /edit/<id> · Abrir a edição

Por que existe

Mostra os dados atuais em um formulário antes da alteração.

O que fazer

  • Receber id como parâmetro da função
  • Buscar um documento: find_one
  • Renderizar edit.html

Dica

Python@app.route("/edit/<id>", methods=["GET"]) def editar_form(id): pessoa = collection.find_one({"_id": ObjectId(id)}) return render_template("edit.html", pessoa=pessoa)
⚠️Por que ObjectId(id)? O _id no banco é um ObjectId, não texto. Buscar pela string da URL nunca encontra nada.

✏️ Função 4 — templates/edit.html e teste

templates/edit.html

Jinja2<form action="/edit/{{ pessoa._id }}" method="POST"> <input type="text" name="name" value="{{ pessoa.name }}"> <input type="text" name="surname" value="{{ pessoa.surname }}"> <a href="/show">Voltar</a> <button type="submit">Salvar</button> </form>

Como testar

  • Em /show clique em Editar
  • Esperado: campos já preenchidos
Terminalcurl http://localhost:3002/edit/COLE_O_ID_AQUI

Descubra o id: db.crud.find({}, {name: 1}).

ℹ️Atenção: com um id válido mas inexistente, esta versão simples devolve 200 com formulário vazio (o Jinja2 não reclama de valor ausente). A versão do repositório resolve com abort(404): é o Desafio Nível 2.

🔄 Função 5 — POST /edit/<id> · Atualizar (UPDATE)

Por que existe

Grava no banco o que foi alterado no formulário.

O que fazer

  • Filtro: qual documento (_id)
  • Mudança: $set com os novos valores
  • Redirecionar para /show

Dica

Python@app.route("/edit/<id>", methods=["POST"]) def editar_salvar(id): collection.update_one( {"_id": ObjectId(id)}, {"$set": { "name": request.form["name"], "surname": request.form["surname"], }}, ) return redirect("/show")
Terminalcurl -i -X POST http://localhost:3002/edit/COLE_O_ID_AQUI \ -d "name=Ana Maria" -d "surname=Silva" # 302 FOUND
mongoshdb.crud.find({ name: "Ana Maria" }) // mesmo _id de antes db.crud.countDocuments() // não aumentou

🗑 Função 6 — GET /delete/<id> · Deletar (DELETE)

Por que existe

Remove um cadastro errado ou duplicado.

Dica

Python@app.route("/delete/<id>") def deletar(id): collection.delete_one({"_id": ObjectId(id)}) return redirect("/show")

Teste

  • Clique em Deletar no Bruno
  • Esperado: ele some da lista
Terminalcurl -i http://localhost:3002/delete/COLE_O_ID_AQUI # 302

Conferir no banco

mongoshdb.crud.find({ name: "Bruno" }) // [] db.crud.countDocuments() // 1
⚠️Apagar por GET é arriscado: um link ou robô pode disparar. Aqui é só para estudo; em API real use DELETE e confirmação.
