🎯 O que vamos revisar?

Usuários

Nome, e-mail, telefone e senha protegida com hash.

Livros

Adicionar um livro ou vários livros em lote.

API

GET, POST, PUT, DELETE, body, rotas e status.

💡O objetivo é saber explicar o caminho da requisição, não decorar cada linha.

🌐 Quem participa?

Postman

Cliente que envia método, URL, headers e JSON.

Express

Servidor que recebe a requisição e escolhe a resposta.

MongoDB

Banco que armazena documentos nas coleções.

Fluxo: Postman → rota Express → validação → MongoDB → status + JSON.

👤 O cadastro do usuário

POST /api/usuarios{ "nome": "Ana Aluna", "email": "ana@example.com", "telefone": "81999999999", "senha": "segredo123" }

Validação

Campos obrigatórios, e-mail válido, senha com ao menos seis caracteres e e-mail único.

Segurança

bcrypt.hash transforma a senha em hash. A senha original nunca é salva nem devolvida.

1️⃣ Primeiro: servidor mínimo

Antes de banco e pastas, vamos provar que o servidor responde.

server-simples.jsconst express = require('express') const app = express() const port = 3005 app.get('/teste', (req, res) => { res.status(200).json({ mensagem: 'Servidor funcionando!' }) }) app.listen(port, () => { console.log(`http://localhost:${port}`) })

Primeiro identificamos: biblioteca, aplicação, porta, rota e resposta.

2️⃣ GET: visualizar no Postman

Passo a passo

  1. Execute node server-simples.js.
  2. Abra o Postman.
  3. Escolha GET.
  4. Digite http://localhost:3005/teste.
  5. Clique em Send.

Resposta

200 OK{ "mensagem": "Servidor funcionando!" }

O Postman é o cliente; o arquivo é o servidor.

🔁Se aparece ECONNREFUSED, o servidor não está rodando ou a porta está diferente.

3️⃣ POST simples: enviar um body

Agora o servidor recebe dados. Acrescente o middleware JSON e uma lista temporária:

server-simples.jsapp.use(express.json()) const usuarios = [] app.post('/usuarios', (req, res) => { const usuario = req.body usuarios.push(usuario) res.status(201).json(usuario) })
Postman — Body raw JSON{"nome":"Ana","email":"ana@example.com"}

Envie POST http://localhost:3005/usuarios e veja o 201 Created.

4️⃣ Criar o app.js: responsabilidade da aplicação

Quando o teste simples funciona, separamos a aplicação do ato de ligar a porta.

src/app.jsconst express = require('express') function createApp({ store }) { const app = express() app.use(express.json()) app.get('/api/status', (req, res) => { res.status(200).json({ status: 'ok' }) }) app.get('/api/usuarios', async (req, res) => { const usuarios = await store.listUsers() res.status(200).json(usuarios) }) return app } module.exports = { createApp }

app.js descreve o que a aplicação faz: middleware, rotas e respostas.

5️⃣ Criar o server.js: iniciar o processo

src/server.jsrequire('dotenv').config() const { createApp } = require('./app') const { MemoryStore } = require('./store') async function startServer() { const port = Number(process.env.PORT) || 3005 const store = new MemoryStore() const app = createApp({ store }) app.listen(port, () => { console.log(`Servidor em http://localhost:${port}`) }) } startServer()

server.js prepara dependências, escolhe a porta e inicia. Depois substituímos MemoryStore pelo MongoDB.

6️⃣ Criar o store.js: responsabilidade dos dados

As rotas não precisam saber se os dados estão em memória ou no MongoDB.

src/store.js — primeira versãoclass MemoryStore { constructor() { this.users = [] } async listUsers() { return this.users } async createUser(user) { this.users.push(user) return user } } module.exports = { MemoryStore }
🧩Começar em memória ajuda a entender GET e POST. Depois criamos MongoStore com os mesmos nomes de função.

7️⃣ Palavras novas: entender sem decorar

Funções e fluxo

function cria uma função; => é uma forma curta. async avisa que uma função espera uma tarefa. await espera o resultado.

Dados

typeof verifica o tipo. undefined significa que um valor não foi informado. trim() remove espaços do começo e do fim.

Decisões

if decide; try/catch tenta executar e captura uma falha. Primeiro compreendemos o caminho feliz; depois tratamos erros.

...document

O spread copia propriedades de um objeto para outro. Ele ajuda a montar uma resposta sem alterar o documento original.

Esses conceitos serão aprofundados no módulo seguinte; aqui basta reconhecer a função que cada um cumpre.

8️⃣ Da memória para o MongoDB

Antes

const store = new MemoryStore()

Os dados desaparecem ao reiniciar.

Depois

const store = await MongoStore.connect( process.env.MONGODB_URI, process.env.MONGODB_DB )

Os dados ficam persistidos em usuarios e livros.

As rotas continuam chamando listUsers, createUser, updateUser e deleteUser. Só muda quem executa o acesso aos dados.

9️⃣ Progressão até o CRUD completo

  1. Servidor simples: uma rota GET e uma resposta.
  2. POST sem banco: body JSON e lista em memória.
  3. app.js: rotas separadas do início do servidor.
  4. server.js: porta, dotenv e conexão.
  5. store.js: operações de dados.

🔍 GET: listar e localizar

Todos

GET http://localhost:3005/api/usuarios

Retorna a lista com status 200.

Por ID

GET http://localhost:3005/api/usuarios/ID_DO_USUARIO

Retorna 200 ou 404.

O método é o mesmo, mas o parâmetro na rota muda o que queremos consultar.

✏️ PUT e DELETE: alterar e remover

Atualizar

PUT /api/usuarios/ID_DO_USUARIO {"telefone":"81988888888"}

Resposta: 200. Envie somente os campos que mudar.

Excluir

DELETE /api/usuarios/ID_DO_USUARIO

Resposta: 204 sem corpo, ou 404.

📚 Livros: um ou vários

Um livro

POST /api/livros {"titulo":"Dom Casmurro","autor":"Machado de Assis"}

Resposta 201.

Lote

POST /api/livros/lote {"livros":[ {"titulo":"Vidas Secas","autor":"Graciliano Ramos"}, {"titulo":"O Cortiço","autor":"Aluísio Azevedo"} ]}

Uma requisição cria vários documentos.

🧯 Servidor fora e cliente sem acesso

Servidor fora

O Postman não recebe HTTP. No frontend, fetch entra no catch por erro de rede.

Banco fora

O servidor está ligado, mas uma operação pode responder 503 Service Unavailable.

Frontendtry { const resposta = await fetch('/api/usuarios') if (!resposta.ok) throw new Error(`HTTP ${resposta.status}`) } catch (erro) { mensagem.textContent = 'Não foi possível acessar a API.' }
