📦 CSS3 — Box Model e Flexbox

Box Model

CSS /* Todo elemento é uma CAIXA */ .card { /* Conteúdo */ width: 300px; /* Espaço interno */ padding: 16px; /* Borda */ border: 1px solid #e5e7eb; /* Espaço externo */ margin: 12px; /* Truque: padding não soma na width */ box-sizing: border-box; }

Flexbox (1 direção)

CSS /* Container flex */ .navbar { display: flex; justify-content: space-between; align-items: center; gap: 16px; } /* Cards lado a lado */ .cards-container { display: flex; flex-wrap: wrap; gap: 24px; } .card { flex: 1 1 300px; /* cresce, encolhe, base */ }
⚠️ Sempre use box-sizing: border-box! Sem isso, padding e border somam na largura total.

HTML • FUNDAMENTOS

🏗️ HTML é a estrutura da página

HTML significa HyperText Markup Language. Ele não é uma linguagem de programação: é uma linguagem de marcação que descreve o significado e a organização do conteúdo que o navegador deve exibir.

Elemento

HTML<p class="intro">Olá, turma!</p>

A tag de abertura, o conteúdo e a tag de fechamento formam um elemento. `class` é um atributo que fornece informação extra.

Como o navegador pensa

1. Lê o arquivo→2. Monta o DOM→3. Renderiza

O navegador transforma o texto HTML em uma árvore de objetos que poderá receber estilo e comportamento.

💡Semântica: escolha a tag pelo significado. Use `<button>` para uma ação e `<a>` para navegar para outro endereço.
HTML • PRODUTIVIDADE

⚡ Emmet `html:5` cria o esqueleto

No VS Code, escreva html:5 em um arquivo `.html` e pressione Tab ou Enter. O Emmet expande a abreviação para um documento inicial.

Abreviação

EMMEThtml:5
🧩Abreviações descrevem estruturas usando uma sintaxe parecida com seletores CSS: `nav>ul>li*3` cria uma navegação com três itens.

Expansão principal

HTML<!doctype html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>Document</title> </head> <body></body> </html>

Atalho útil não substitui compreensão: leia cada parte do esqueleto antes de começar a preencher o conteúdo.

HTML • DOCUMENTO

🔬 Anatomia do HTML gerado

HTML<!doctype html> <!-- modo HTML5 --> <html lang="pt-BR"> <!-- raiz + idioma --> <head> <!-- metadados --> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <link rel="stylesheet" href="styles.css"> <title>Minha página</title> </head> <body> <!-- conteúdo visível --> <header>Cabeçalho</header> <main>Conteúdo principal</main> <footer>Rodapé</footer> </body> </html>

O que fica onde?

  • `doctype`: informa que o documento usa HTML moderno.
  • `html`: envolve toda a página e declara o idioma.
  • `head`: configura título, charset, viewport, CSS e metadados.
  • `body`: recebe textos, imagens, formulários e scripts visíveis ou interativos.
  • `link`: conecta um arquivo externo, como `styles.css`.
⚠️Se o `meta viewport` faltar, a página pode parecer “espremida” no celular.
HTML • CONTEÚDO

✍️ Texto: organize a leitura

O HTML deve formar uma hierarquia de leitura. Use apenas um título principal para a página e desça pelos níveis conforme a organização do conteúdo.

HTML<h1>Guia de estudos</h1> <h2>Primeiros passos</h2> <h3>Preparar o ambiente</h3> <p>Um parágrafo apresenta uma ideia completa.</p> <p>Use <strong>strong</strong> para importância e <em>em</em> para ênfase.</p> <hr> <blockquote>Aprender é construir e testar.</blockquote>

HTML • ELEMENTOS ESSENCIAIS

🔗 Imagens, links e listas

HTML<a href="https://developer.mozilla.org/" target="_blank" rel="noopener"> Consultar a MDN </a> <img src="imagens/perfil.jpg" alt="Estudante sorrindo em frente ao computador" width="320"> <ul> <li>HTML</li> <li>CSS</li> </ul> <ol> <li>Planejar</li> <li>Construir</li> </ol>

Boas decisões

  • Link: `href` define o destino; descreva o texto do link.
  • Imagem: `src` aponta para o arquivo e `alt` descreve a imagem.
  • Lista não ordenada: use `ul` quando a ordem não importa.
  • Lista ordenada: use `ol` quando existe sequência.
  • Caminhos: `imagens/foto.jpg` é relativo ao arquivo atual.
🖼️Não use imagem apenas para carregar texto. O conteúdo importante deve existir como texto acessível.

🧭 Dê nome às regiões da página

HTML • INTERAÇÃO

📝 Formulários: coletar dados com significado

HTML<form action="/inscricoes" method="post"> <label for="nome">Nome completo</label> <input id="nome" name="nome" type="text" placeholder="Digite seu nome" required> <label for="email">E-mail</label> <input id="email" name="email" type="email" required> <label for="turma">Turma</label> <select id="turma" name="turma"> <option value="ds1">DS 1</option> <option value="ds2">DS 2</option> </select> <label for="mensagem">Mensagem</label> <textarea id="mensagem" name="mensagem" rows="4"></textarea> <label><input type="checkbox" name="termos" required> Aceito os termos</label> <button type="submit">Enviar inscrição</button> </form>

Peças do formulário

  • form agrupa dados e define o envio.
  • label for conecta o rótulo ao campo pelo `id`.
  • input recebe textos, números, e-mail, senha, data, checkbox e radio.
  • textarea recebe textos longos.
  • select/option oferece escolhas.
  • button dispara ações; declare o `type`.
✅Use `type="email"`, `required`, `min`, `max` e `pattern` para aproveitar validações nativas antes do JavaScript.

CSS • DECORAÇÃO COM PROPÓSITO

🖼️ Fundos, imagens e estados

CSS.hero { min-height: 360px; background: linear-gradient(rgba(15,23,42,.68), rgba(15,23,42,.68)), url("imagens/laboratorio.jpg") center / cover; color: white; display: grid; place-items: center; text-align: center; } .avatar { width: 96px; aspect-ratio: 1; object-fit: cover; border-radius: 50%; } .card:nth-child(even) { background: #EFF6FF; } input:focus { border-color: #2563EB; } input:invalid:not(:placeholder-shown) { border-color: #DC2626; } button:disabled { opacity: .55; cursor: not-allowed; }

Imagem no conteúdo ou no fundo?

  • Use `<img>` quando a imagem é parte do significado e precisa de `alt`.
  • Use `background-image` quando a imagem é decorativa ou compõe o ambiente visual.
  • Use `object-fit: cover` para preencher um recorte sem deformar a imagem.
  • Use contraste entre texto e fundo; uma camada escura sobre a foto ajuda a leitura.
🎯Pseudo-classes como `:hover`, `:focus`, `:checked` e `:disabled` descrevem estados sem JavaScript.

JavaScriptasync function carregarProdutos() { const lista = document.querySelector('#lista'); lista.textContent = 'Carregando...'; try { const resposta = await fetch('/api/produtos'); if (!resposta.ok) { throw new Error(`HTTP ${resposta.status}`); } const produtos = await resposta.json(); renderizarProdutos(produtos); } catch (erro) { console.error(erro); lista.textContent = 'Não foi possível carregar os produtos.'; } } carregarProdutos();

Contrato de uma requisição

URL→servidor→resposta→JSON
  • fetch inicia uma requisição.
  • await aguarda uma Promise sem bloquear a interface.

  • response.json() converte o corpo para dados JavaScript.
  • try/catch transforma falha técnica em feedback compreensível.

BACKEND • NODE.JS

🚀 Um servidor mínimo com Express

server.jsimport express from 'express'; const app = express(); const PORT = 3000; const recados = []; app.use(express.json()); app.get('/api/recados', (req, res) => { res.json(recados); }); app.post('/api/recados', (req, res) => { const texto = String(req.body.texto || '').trim(); if (!texto) { return res.status(400).json({ erro: 'Texto obrigatório' }); } const recado = { id: Date.now(), texto }; recados.push(recado); res.status(201).json(recado); }); app.listen(PORT, () => { console.log(`Servidor em http://localhost:${PORT}`); });

O que cada parte faz?

  • express() cria a aplicação.
  • express.json() lê corpos JSON.
  • app.get e app.post registram rotas.
  • req.body recebe dados enviados.
  • res.status().json() devolve status e JSON.
  • listen abre a porta para receber requisições.
🧠Esse array desaparece quando o servidor reinicia. Para produção, substitua-o por um banco de dados e trate autenticação, autorização e validação.

  • Middleware: executa antes/depois da rota.

MERCADO • PROCESSO

🧭 Como uma equipe entrega uma feature web

1Entenderrequisito, usuário, conteúdo e critérios de aceite.
2ModelarHTML semântico, estados de tela e contrato de API.
3ConstruirCSS modular, JS organizado e commits pequenos.
4Testarteclado, tamanhos, erro, vazio, rede e dados inválidos.
5Revisaracessibilidade, performance, segurança e legibilidade.
6Publicardeploy, monitoramento, documentação e manutenção.

Checklist técnico

  • HTML validado e semântico.
  • CSS responsivo e com foco visível.
  • JS sem erros no console.
  • API com status e mensagens coerentes.

Checklist humano

  • Textos compreensíveis.
  • Feedback para cada ação.
  • Contraste e leitura confortáveis.
  • README para outra pessoa executar.
