🧠 Lógica — Revisão AV1

Variáveis, tipos, condicionais e loops

📌 Tópicos-Chave

  • Diferença entre let, const e var
  • Conversão de tipos: parseInt, parseFloat, String()
  • Operadores: === vs ==, &&, ||, !
  • Estruturas: if/else if/else, switch

⚠️ Pegadinhas Comuns

  • "5" + 3 → "53" (concatenação!)
  • "5" - 3 → 2 (coerção numérica)
  • const em array: pode alterar itens, não reatribuir
  • for com <= vs < (off-by-one)

📝 Exercício-Modelo

JavaScript // Filtrar maiores de idade const alunos = [ { nome: 'Ana', idade: 17 }, { nome: 'Carlos', idade: 19 }, { nome: 'Bia', idade: 16 }, { nome: 'Pedro', idade: 21 } ]; const maiores = alunos.filter(a => a.idade >= 18); const nomes = maiores.map(a => a.nome); console.log(nomes); // ['Carlos', 'Pedro'] // DOM: mostrar nomes na tela const lista = document.querySelector('#lista'); nomes.forEach(n => { lista.innerHTML += `<li>${n}</li>`; });
⚠️ Pegadinha: filter retorna NOVO array (não modifica o original). map também. Sempre use const resultado = ...

🧠 Lógica — Revisão AV3

Fetch API, async/await e integração com APIs

📌 Tópicos-Chave

  • Promises: .then(), .catch()
  • async/await — sintaxe moderna
  • fetch() — GET e POST
  • JSON.parse() e JSON.stringify()
  • Try/catch para tratamento de erros
  • Integração: buscar dados de API e exibir no DOM

📝 Exercício-Modelo

JavaScript // Buscar CEP e mostrar endereço async function buscarCEP(cep) { try { const resp = await fetch( `https://viacep.com.br/ws/${cep}/json/` ); const dados = await resp.json(); if (dados.erro) { alert('CEP não encontrado'); return; } document.querySelector('#endereco') .textContent = `${dados.logradouro}, ${dados.bairro} - ${dados.localidade}`; } catch (error) { alert('Erro de conexão'); } }
💡 Dica: Sempre use try/catch com async/await. Erros de rede são comuns e precisam de tratamento.

🎨 UI/UX — Revisão

🔄 Ciclo DCU (Design Centrado no Usuário)

  1. Pesquisa: entender quem é o usuário
  2. Definição: personas + jornada
  3. Ideação: brainstorm de soluções
  4. Prototipação: wireframe → alta fidelidade
  5. Teste: validar com usuários reais
  6. Iteração: ajustar e repetir

👤 Personas

  • Personagem fictício baseado em dados reais
  • Nome, idade, profissão, dores, objetivos
  • Guia decisões de design (para QUEM estou fazendo?)

📋 10 Heurísticas de Nielsen

  1. Visibilidade do status do sistema
  2. Compatibilidade com o mundo real
  3. Controle e liberdade do usuário
  4. Consistência e padrões
  5. Prevenção de erros
  6. Reconhecimento em vez de memorização
  7. Flexibilidade e eficiência
  8. Design estético e minimalista
  9. Ajuda a reconhecer e recuperar erros
  10. Ajuda e documentação
🎯 Na prova: Saber identificar QUAL heurística está sendo violada em um exemplo de interface.

🎯 Simulado Integrado — 5 Questões Modelo

Q1 (Lógica): Escreva uma função maiorDeIdade(pessoas) que recebe um array de objetos {nome, idade} e retorna apenas os nomes dos maiores de 18 anos.

Q2 (HTML/CSS): Crie um card responsivo com imagem, título e botão. Use Flexbox para alinhar. Em mobile, o card deve ocupar 100% da largura; em desktop, 3 cards por linha.

Q3 (Redes): Um servidor web roda na porta 3000 de um computador com IP 192.168.1.50. Qual URL um colega da mesma rede deve digitar para acessar? O que acontece se usar a porta 80?

Q4 (UI/UX): Um formulário de cadastro não mostra mensagem de erro quando o e-mail é inválido. Qual heurística de Nielsen está sendo violada? Proponha uma solução.

Q5 (Integração): Usando fetch, busque dados de https://api.exemplo.com/alunos e exiba os nomes em uma lista <ul>. Trate possíveis erros de rede.

⏱️ Tempo sugerido: 15 min por questão = 1h15 total. Na prova real: 2h para 10 questões.

💡 Dicas de Prova — Estratégias para ir Bem

⏱️ Gestão de Tempo

  • Leia TODAS as questões antes de começar
  • Comece pelas que você tem certeza
  • Reserve 10 min finais para revisar
  • Não gaste mais de 15 min numa questão — pule e volte
  • Questões de código: escreva pseudocódigo primeiro

📖 Como Ler Enunciados

  • Sublinhe as palavras-chave
  • "Retorne" ≠ "Imprima" ≠ "Exiba"
  • "Array de objetos" → saiba a estrutura
  • Identifique: entrada, processamento, saída
  • Se pede "explique" → não basta código

❌ Erros Comuns a Evitar

ErroComo Evitar
Esquecer return na funçãoSempre releia: "a função deve RETORNAR"

HTML sem fechar tagsIndente corretamente, conte aberturas/fechamentos
CSS sem unidade (16 em vez de 16px)Sempre coloque px, rem, %, vh

✅ Q1 — Lógica

JavaScript function maiorDeIdade(pessoas) { return pessoas .filter(p => p.idade >= 18) .map(p => p.nome); } // POR QUE: filter seleciona, map extrai // ERRADO: usar forEach + push (funciona // mas não é idiomático)

✅ Q3 — Redes

R: http://192.168.1.50:3000

Se usar porta 80: erro de conexão, pois o servidor está na 3000, não na 80.

POR QUE: a porta faz parte do endereço. Porta errada = ninguém atende.

✅ Q4 — UI/UX

Heurística violada: #9 — "Ajuda a reconhecer e recuperar erros"

Solução: Mostrar mensagem vermelha abaixo do campo: "E-mail inválido. Use o formato nome@dominio.com"

POR QUE: O usuário precisa saber O QUE errou e COMO corrigir.

✅ Q2 — HTML/CSS (resumo)

Usar display: flex; flex-wrap: wrap; gap: 16px no container. Cada card com flex: 1 1 300px (cresce, encolhe, base 300px).

POR QUE: flex-wrap permite que os cards pulem de linha quando não cabem. A base de 300px garante 3 por linha em telas largas.
