🧰 Comece pelo caminho mais simples

Em todo computador

  1. Node.js LTS instalado.
  2. VS Code e extensão Expo Tools.
  3. Conta gratuita em expo.dev.
  4. Celular Android/iOS com Expo Go.

No celular Android

  1. Abra Google Play.
  2. Instale Expo Go.
  3. Conecte celular e computador na mesma rede.
  4. Use o leitor de QR do Expo Go.

Para início de aula, esse caminho dispensa Android Studio e emulador.

Quando usar Android Studio

Use quando o projeto precisar de emulador, depuração USB, bibliotecas nativas ou development build.

  • Instale JDK 17 e Android Studio.
  • Configure ANDROID_HOME.
  • Adicione platform-tools ao PATH.
  • Confirme com adb --version.

🍎 macOS — mesmo projeto, ambiente específico

Começo rápido

Terminalnode --version npx create-expo-app@latest tarefas-ete cd tarefas-ete npx expo start

Com Expo Go, escaneie o QR usando a câmera do iPhone ou o app no Android.

Android local no macOS

  • Instale Android Studio e crie um emulador.
  • Instale OpenJDK 17 e configure JAVA_HOME.
  • Configure ANDROID_HOME e platform-tools.

iOS nativo exige macOS; Android pode ser desenvolvido em Windows, macOS ou Linux.

🧱 View, Text e Pressable substituem div, p e button

HTML mental

HTML<div> <p>Olá</p> <button>Salvar</button> </div>

React Native

TSX<View> <Text>Olá</Text> <Pressable onPress={salvar}> <Text>Salvar</Text> </Pressable> </View>

A interface é descrita com TSX, mas não há tags HTML no app nativo. Use StyleSheet ou bibliotecas de estilo compatíveis.

🎨 Flexbox é o sistema de layout padrão

Estilos

TSXconst styles = StyleSheet.create({ card: { backgroundColor: '#FFFFFF', padding: 16, borderRadius: 12, gap: 8 }, title: { fontSize: 22, fontWeight: '700' } });

Layout

TSXcontainer: { flex: 1, padding: 24, justifyContent: 'center', alignItems: 'stretch' }

flex: 1 ocupa a área disponível. O padrão de direção é coluna, ao contrário de muitos layouts web.

🧠 useState liga o toque à interface

TSXimport { useState } from 'react'; import { Text, TextInput, View } from 'react-native'; export default function Perfil() { const [nome, setNome] = useState(''); return ( <View> <TextInput value={nome} onChangeText={setNome} placeholder="Seu nome" /> <Text>Olá, {nome || 'turma'}!</Text> </View> ); }

O usuário altera o campo; onChangeText atualiza o estado; o React redesenha o texto que depende de nome.

➕ Separe entrada, regra e resultado

Dados de entrada

Dois TextInput guardam texto. Converta para número apenas ao calcular.

TSXconst [primeiro, setPrimeiro] = useState(''); const [segundo, setSegundo] = useState(''); const [resultado, setResultado] = useState<number | null>(null);

Regra

TSXfunction somar() { const a = Number(primeiro); const b = Number(segundo); if (Number.isNaN(a) || Number.isNaN(b)) { return Alert.alert('Atenção', 'Digite dois números.'); } setResultado(a + b); }

✅ Gabarito — Calculadora com soma

TSX<TextInput keyboardType="numeric" value={primeiro} onChangeText={setPrimeiro} placeholder="Primeiro número" /> <TextInput keyboardType="numeric" value={segundo} onChangeText={setSegundo} placeholder="Segundo número" /> <Pressable style={styles.button} onPress={somar}> <Text style={styles.buttonText}>Somar</Text> </Pressable> {resultado !== null && ( <Text>Resultado: {resultado}</Text> )}
🧪Teste 2 + 3, números decimais e campo vazio. Cada cenário revela uma parte do comportamento esperado.

📋 CRUD no celular começa pelo estado local

Modelo de tarefa

TypeScripttype Tarefa = { id: string; titulo: string; concluida: boolean; }; const [tarefas, setTarefas] = useState<Tarefa[]>([]);

Operações

Createadiciona tarefa ao array
ReadFlatList mostra tarefas
Updatemarca concluída ou edita título
Deleteremove pelo id

O estado local ensina a regra. Firebase entra para tornar os dados persistentes e compartilhados.

✏️ Atualize uma lista sem alterar o estado diretamente

TSXfunction criar(titulo: string) { const tarefa = { id: crypto.randomUUID(), titulo, concluida: false }; setTarefas(lista => [...lista, tarefa]); } function alternar(id: string) { setTarefas(lista => lista.map(t => t.id === id ? { ...t, concluida: !t.concluida } : t )); } function remover(id: string) { setTarefas(lista => lista.filter(t => t.id !== id)); }

Crie novos arrays e novos objetos. Alterar diretamente uma tarefa existente pode impedir o React de atualizar a interface corretamente.

☁️ Firestore transforma estado local em dados persistentes

Configuração inicial

  1. Crie projeto no Firebase Console.
  2. Adicione aplicativo Web ao projeto Expo.
  3. Copie a configuração pública para firebase.ts.
  4. Ative Firestore em modo de teste apenas para desenvolvimento inicial.
Terminalnpx expo install firebase

Modelo recomendado

Firestoreusuarios/{uid}/tarefas/{tarefaId} { titulo: 'Estudar Expo', concluida: false, criadaEm: serverTimestamp() }

O UID na rota dos dados ajuda a estruturar regras para que um estudante leia apenas suas próprias tarefas.

🔥 CRUD com Firestore

TypeScriptimport { addDoc, collection, deleteDoc, doc, updateDoc } from 'firebase/firestore'; await addDoc(collection(db, 'usuarios', uid, 'tarefas'), { titulo, concluida: false, criadaEm: new Date() }); await updateDoc(doc(db, 'usuarios', uid, 'tarefas', id), { concluida: true }); await deleteDoc(doc(db, 'usuarios', uid, 'tarefas', id));
🔒Configuração do Firebase não substitui regras. Antes de publicar, escreva regras de Firestore que comparem o UID autenticado com o dono do documento.

🪪 Usuário autenticado define o dono dos dados

Cadastro/Login

TypeScriptimport { createUserWithEmailAndPassword, signInWithEmailAndPassword } from 'firebase/auth'; const credencial = await signInWithEmailAndPassword( auth, email, senha ); const uid = credencial.user.uid;

Regra Firestore (ideia)

Rulesmatch /usuarios/{uid}/tarefas/{tarefaId} { allow read, write: if request.auth != null && request.auth.uid == uid; }

Teste com dois usuários. Se um enxerga a tarefa do outro, a regra ainda não está segura.

📦 APK é para instalar e testar; AAB é para Play Store

Perfil de teste

eas.json{ "build": { "preview": { "android": { "buildType": "apk" } }, "production": {} } }
Terminaleas build -p android --profile preview

Use correto

Envie o link do APK para um aparelho de teste ou instale com ADB. O APK não é o arquivo para uma nova publicação no Google Play.

O build de produção gera AAB por padrão: o formato aceito pela Play Store para novos apps.

Produção

Terminaleas build --platform android --profile production eas submit --platform android

Crie antes o app no Play Console e configure a credencial de service account no EAS. O primeiro envio vai para teste interno e permanece em rascunho até completar a ficha.

🚀 Um envio à Play Store é uma sequência verificável

  1. Crie o app no Play Console com nome e package name definitivos.
  2. Preencha ficha da loja, classificação de conteúdo, política de privacidade e Segurança dos dados.
  3. Crie conta de serviço Google, dê permissão no Play Console e envie a chave ao EAS com segurança.
  4. Gere AAB: eas build --platform android --profile production.
  5. Envie para teste interno com eas submit --platform android ou pelo console.
  6. Teste com pessoas convidadas, corrija falhas e só então promova o release.
⚠️Nunca versione a chave JSON da conta de serviço, senhas ou arquivos com segredos no Git.

🧩 Desafio 1
Calculadora de média

Inputs, estado, condição e interface

📝 Exercício 1 — Média da turma

Construa

  1. Crie três campos de nota com teclado numérico.
  2. Crie botão Calcular média.
  3. Mostre média com uma casa decimal.
  4. Mostre aprovado, recuperação ou reprovado.
  5. Trate campo vazio e número inválido.

Critérios de interface

  • Label visível para cada campo.
  • Botão com contraste e área de toque.
  • Resultado não aparece antes do cálculo.
  • Mensagem de erro compreensível.

✅ Gabarito 1 — Regra da média

TSXfunction calcularMedia() { const notas = [nota1, nota2, nota3].map(Number); if (notas.some(Number.isNaN)) { return Alert.alert('Atenção', 'Preencha as três notas.'); } const media = notas.reduce((soma, nota) => soma + nota, 0) / 3; const situacao = media >= 7 ? 'Aprovado' : media >= 5 ? 'Recuperação' : 'Reprovado'; setResultado({ media, situacao }); }

Extensão: permita limpar campos, calcule a nota mínima da recuperação e transforme a regra em uma função testável.

📝 Exercício 2 — Lista de tarefas persistente

Obrigatório

  1. Login com e-mail e senha.
  2. Criar tarefa com título obrigatório.
  3. Listar tarefas do usuário autenticado.
  4. Concluir, editar e remover tarefa.
  5. Exibir carregamento e erro.

Segurança

  1. Use UID no caminho Firestore.
  2. Escreva regra que bloqueie usuário não autenticado.
  3. Teste com duas contas.
  4. Não use modo de teste em produção.

✅ Gabarito 2 — Leitura com filtro por usuário

TSXimport { collection, onSnapshot, orderBy, query } from 'firebase/firestore'; useEffect(() => { if (!uid) return; const tarefasRef = collection(db, 'usuarios', uid, 'tarefas'); const q = query(tarefasRef, orderBy('criadaEm', 'desc')); return onSnapshot(q, snapshot => { setTarefas(snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }))); }); }, [uid]);

O filtro no caminho organiza os dados; a regra Firestore garante que a organização também seja uma proteção real.
