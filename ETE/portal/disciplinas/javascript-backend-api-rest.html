Projeto guiado

Uma API de tarefas da turma: usuários se cadastram, fazem login, criam tarefas e consultam apenas seus próprios dados.

🧠Frontend mostra a interface; backend protege regras, dados e acessos.

🏗️ Backend é a parte que trabalha longe da tela

Responsabilidades

  • Receber uma requisição.
  • Validar dados e permissões.
  • Consultar ou alterar o banco.
  • Responder com status e JSON.

O que não deve fazer

  • Confiar em dados enviados pelo navegador.
  • Expor senha, token ou segredo.
  • Permitir que todo usuário acesse todos os dados.
  • Retornar um erro técnico sem explicação útil.

Header

Cadastro seguro

Terminalnpm install bcrypt jsonwebtoken

🪪 Token identifica o usuário em cada chamada

Gerar token no login

JavaScriptimport jwt from 'jsonwebtoken'; const token = jwt.sign( { sub: usuario.id }, process.env.JWT_SECRET, { expiresIn: '1h' } ); res.json({ token });

Proteger uma rota

JavaScriptfunction autenticar(req, res, next) { const [, token] = req.headers.authorization?.split(' ') ?? []; if (!token) return res.sendStatus(401); req.user = jwt.verify(token, process.env.JWT_SECRET); next(); } app.get('/tarefas', autenticar, listarTarefas);

🌍 CORS define quais sites podem chamar sua API

Durante desenvolvimento

JavaScriptimport cors from 'cors'; app.use(cors({ origin: 'http://localhost:5173', methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'] }));

Regra prática

Postman e Bruno não dependem do CORS porque não são páginas web. Já um frontend no navegador é bloqueado quando a API não autoriza sua origem.

Em produção, substitua * por domínios conhecidos e configure credenciais conscientemente.

📝 Exercício 4 — Filtre e pagine tarefas

Problema

Implemente GET /tarefas?status=aberta&pagina=2&limite=5. A API deve devolver apenas tarefas compatíveis e metadados de paginação.

  1. pagina padrão é 1 e não pode ser menor que 1.
  2. limite padrão é 10 e máximo é 50.
  3. status aceita aberta ou concluida.

Teste de aceitação

HTTPGET /tarefas?status=aberta&pagina=1&limite=2 Accept: application/json Authorization: Bearer {{token}}

Entregue um JSON com pagina, limite e dados, sem expor tarefas de outros usuários.

✅ Gabarito 4 — Consulta previsível

JavaScriptapp.get('/tarefas', autenticar, async (req, res) => { const pagina = Math.max(Number(req.query.pagina) || 1, 1); const limite = Math.min(Number(req.query.limite) || 10, 50); const status = req.query.status; if (status && !['aberta', 'concluida'].includes(status)) { return res.status(400).json({ error: 'STATUS_INVALID' }); } const params = [req.user.sub]; let sql = 'SELECT id, titulo, concluida FROM tarefas WHERE usuario_id = ?'; if (status) { sql += ' AND concluida = ?'; params.push(status === 'concluida'); } sql += ' LIMIT ? OFFSET ?'; params.push(limite, (pagina - 1) * limite); const [dados] = await db.execute(sql, params); res.json({ pagina, limite, dados }); });

Use placeholders SQL. O status deve filtrar, enquanto a autorização deve limitar os dados ao usuário autenticado.

✅ Gabarito 7 — Token curto e previsível

JavaScriptapp.post('/auth/login', async (req, res, next) => { try { const { email, senha } = req.body; const usuario = await buscarPorEmail(email); const valido = usuario && await bcrypt.compare(senha, usuario.senha_hash); if (!valido) return res.status(401).json({ error: 'INVALID_CREDENTIALS' }); const token = jwt.sign( { sub: usuario.id, role: usuario.role }, process.env.JWT_SECRET, { expiresIn: '15m' } ); res.json({ token, expiresIn: '15m' }); } catch (error) { next(error); } });

Missão

✅ Gabarito 9 — Entrada explícita

JavaScriptimport { z } from 'zod'; const tarefaSchema = z.object({ titulo: z.string().trim().min(3).max(120), prioridade: z.enum(['baixa', 'media', 'alta']).default('media'), prazo: z.string().datetime().optional() }).strip(); app.post('/tarefas', autenticar, async (req, res, next) => { const parsed = tarefaSchema.safeParse(req.body); if (!parsed.success) return res.status(400).json({ error: 'VALIDATION_ERROR', fields: parsed.error.flatten().fieldErrors }); try { res.status(201).json(await criarTarefa(req.user.sub, parsed.data)); } catch (error) { next(error); } });

🧪 Exercício 10 — Proteja a tarefa de outra pessoa

Problema

O usuário 12 tenta editar /tarefas/44, mas a tarefa pertence ao usuário 8.

  1. Valide se o id é número inteiro positivo.
  2. Busque a tarefa filtrando também por usuario_id.
  3. Responda 404 se não houver linha encontrada.
  4. Nunca aceite usuario_id enviado no body.

Reflexão

Retornar 404 nesse caso evita revelar que outro usuário possui uma tarefa com esse id. A consulta parametrizada resolve autorização e reduz exposição.

⚠️Um token válido não dá permissão para alterar qualquer recurso.

AND usuario_id = ?', [parsed.data.concluida, id, req.user.sub] ); if (result.affectedRows === 0) return res.status(404).json({ error: 'TASK_NOT_FOUND' }); res.json({ id, ...parsed.data }); } catch (error) { next(error); } });
