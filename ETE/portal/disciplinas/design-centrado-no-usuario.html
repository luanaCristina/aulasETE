🔍 O que é Design Centrado no Usuário?

Uma abordagem de projeto onde todas as decisões são tomadas com base em dados reais sobre os usuários — não em "achismos" da equipe.

💡 Analogia: Imagine um restaurante que cria o cardápio SEM perguntar aos clientes o que gostam. O DCU é como fazer pesquisa ANTES de montar o cardápio.

🔄 O Ciclo do DCU

  1. Pesquisar — Entender o usuário
  2. Definir — Sintetizar insights
  3. Prototipar — Criar soluções
  4. Testar — Validar com usuários

↻ Repetir até acertar!

🎯 Competências desta disciplina

  • Conduzir pesquisa com usuários reais
  • Criar personas baseadas em dados
  • Mapear jornadas identificando dores
  • Prototipar no Figma (baixa/alta fid.)
  • Testar usabilidade e iterar
  • Exportar artefatos para código

📊 Caso Real: iFood vs. 99Food

Mesmo problema (pedir comida), UX radicalmente diferentes dependendo da persona.

CritérioiFood99Food
Público-alvoClasses B/C, 25-45 anosClasses C/D, 18-35 anos
Proposta de valorVariedade + velocidadeMenor preço + cupons
UX principalDescoberta (explorar)Objetivo direto (pedir rápido)
Ponto forteFiltros + avaliaçõesCashback + frete grátis
Ponto fracoExcesso de informaçãoPoucos restaurantes
🎯 Lição: O mesmo problema gera soluções de UX opostas quando a persona muda!

👤 Construindo uma Persona

Uma persona é uma síntese de dados reais — não ficção criativa.

Persona: Mariana Silva, 28 anos

Ocupação: Técnica em Enfermagem — Recife/PE

📱 Digital: Android (85% do tempo), Instagram + WhatsApp

😤 Dores:

  • Não agenda consultas sem fila
  • Apps pedem dados demais
  • Esquece horários de consultas

🎯 Objetivos:

  • Agendar pelo celular em < 2 min
  • Receber lembretes automáticos
  • Histórico médico acessível

"Eu só quero marcar minha consulta sem ligar pra 5 lugares."

⚠️ Erros Comuns

  • ❌ Criar persona ANTES da pesquisa
  • ❌ Dores genéricas ("quer facilidade")
  • ❌ Baseada no próprio perfil do designer
  • ❌ Sem frase-chave emocional

✅ Checklist de Qualidade

  • ✓ Baseada em dados reais (5+ respostas)
  • ✓ Dores específicas e observáveis
  • ✓ Objetivos viram funcionalidades
  • ✓ Frase-chave captura emoção real

🔗 Do Design ao Código

Todo artefato de DCU se transforma em código real nas aplicações Mobile e Web.

A lógica é o fundamento soberano; linguagens e frameworks são apenas sintaxe.

📊 Do Artefato de Design ao Código

Artefato DCUMobile (Expo/RN)Web (HTML/CSS/JS)
PersonaFuncionalidades prioritárias no App.tsxUser Stories → rotas da API
JornadaFluxo de navegação (react-navigation)Sitemap e rotas do frontend
WireframeEstrutura dos componentesHTML semântico
Style GuideArquivo theme.ts (tokens)CSS Custom Properties (:root)
ProtótipoReferência pixel-perfectReferência para CSS + layout
Teste de UsabilidadeIssues → refatoração de UXAjustes no front com dados
⚠️ A MESMA especificação do Figma vira theme.ts no mobile e :root no CSS. O design é UM — a sintaxe se adapta.

🧪 Teste de Usabilidade

Script do Moderador

  1. Introdução (2 min): "Não testamos você — testamos o design."
  2. Tarefas (15 min): 5 tarefas específicas
  3. Pós-teste (5 min): Escala 1-5 + "o que mudaria?"

5 Tarefas de Teste

  1. Agendar consulta com cardiologista
  2. Cancelar essa consulta
  3. Encontrar histórico de consultas
  4. Trocar foto de perfil
  5. Encontrar médico pelo convênio

📊 Métricas

MétricaMeta
Taxa de sucesso≥ 80%
Tempo na tarefa< 30s (simples)
Erros por tarefa≤ 1
SUS Score≥ 68 pontos
💡 Testar com 5 usuários encontra 85% dos problemas (Jakob Nielsen).

Valor: 30% da nota

Valor: 40% da nota

  • Checklist de Acessibilidade
