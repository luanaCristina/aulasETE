Banco

CRUD é uma forma de pensar o ciclo de vida do recurso. Uma API bem organizada transforma esse ciclo em rotas previsíveis.

📨 HTTP é um contrato

Requisição

HTTPPOST /api/alunos Content-Type: application/json {"nome":"Ana","matricula":"1001"}

Resposta

HTTPHTTP/1.1 201 Created Content-Type: application/json {"_id":"...","nome":"Ana"}
✅200 consulta/atualização · 201 criação · 204 exclusão sem corpo · 400 entrada inválida · 404 não encontrado · 500 erro inesperado.

server.jsconst express = require('express') const app = express() const port = 3000 app.get('/api/saudacao', (req, res) => { res.status(200).json({ mensagem: 'Olá, API!' }) }) app.listen(port, () => console.log(`http://localhost:${port}`))

O `express()` cria a aplicação; `app.listen()` abre uma porta para o servidor receber requisições.

🚪 Porta, localhost e ambientes

Porta

Identifica o serviço no computador. A porta 3000 é uma convenção, não uma obrigação.

const port = Number(process.env.PORT) || 3000

Localhost

Indica o próprio computador. A API local pode ser acessada em http://localhost:3000.

Se a porta estiver ocupada, use outra disponível.

⚠️Desenvolvimento, teste e produção podem usar portas, bancos e configurações diferentes.

🧱 Operações CRUD no MongoDB

Create / Read

const { ObjectId } = require('mongodb') await alunos.insertOne({ nome: 'Ana' }) const todos = await alunos.find().toArray() const id = new ObjectId(req.params.id) const aluno = await alunos.findOne({ _id: id })

Update / Delete por _id

const id = new ObjectId(req.params.id) await alunos.updateOne( { _id: id }, { $set: { ativo: true } } ) await alunos.deleteOne({ _id: id })
🆔O MongoDB salva o identificador como _id. Como a URL traz texto, converta com new ObjectId(req.params.id) antes de localizar, atualizar ou excluir.

Na API, valide o formato do ID, escolha o status correto e trate erros.

🛣️ Desenho das rotas

MétodoRotaStatus esperado
GET/api/alunos200 + lista
POST/api/alunos201 + criado
GET/api/alunos/:id200, 400 ou 404
PUT/api/alunos/:id200, 400 ou 404
DELETE/api/alunos/:id204, 400 ou 404
📐Uma rota representa um recurso. O método HTTP explica a intenção da operação.

✅ Criar: validar antes de inserir

Expressapp.post('/api/alunos', async (req, res, next) => { try { const { nome, matricula } = req.body if (!nome?.trim() || !matricula?.trim()) { return res.status(400).json({ erro: 'Nome e matrícula são obrigatórios.' }) } const aluno = { nome: nome.trim(), matricula: matricula.trim() } const result = await alunos.insertOne(aluno) return res.status(201).json({ ...aluno, _id: result.insertedId }) } catch (error) { return next(error) } })

O cliente envia dados; o servidor decide se eles são válidos. A validação do formulário não substitui a validação da API.

🐍 A mesma ideia em Python com Flask

Pythonfrom flask import Flask, jsonify, request app = Flask(__name__) alunos = [] @app.get('/api/alunos') def listar(): return jsonify(alunos), 200 @app.post('/api/alunos') def criar(): dados = request.get_json(silent=True) or {} if not dados.get('nome'): return jsonify(erro='Nome obrigatório'), 400 aluno = {'id': len(alunos) + 1, 'nome': dados['nome']} alunos.append(aluno) return jsonify(aluno), 201 app.run(port=5000, debug=True)

A linguagem muda, mas o contrato HTTP continua: rota, método, JSON e status.

🧪 Testar antes de conectar a tela

Requisição

POSThttp://localhost:3000/api/alunos Content-Type: application/json {"nome":"Ana","matricula":"1001"}

Checklist

  1. Status: 201.
  2. Resposta possui _id.
  3. Faça um GET.
  4. Teste campo ausente: 400.
  5. Teste ID inexistente: 404.

📮 Página 18 — Como usar cada rota no Postman

1. Criar

POST http://localhost:3000/api/alunos Body → raw → JSON {"nome":"Bia","matricula":"1002"}

Envie e copie o _id retornado.

2. Localizar

GET http://localhost:3000/api/alunos/ID_COPIADO

Substitua ID_COPIADO pelo valor real.

3. Atualizar

PUT http://localhost:3000/api/alunos/ID_COPIADO Body → raw → JSON {"nome":"Bia Silva","matricula":"1002"}

Confirme o status 200.

4. Excluir

DELETE http://localhost:3000/api/alunos/ID_COPIADO

Confirme 204 ou a resposta definida na API.
