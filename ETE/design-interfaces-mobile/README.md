## 📖 Sobre a Disciplina

Esta disciplina capacita o aluno a projetar interfaces mobile eficazes, seguindo guidelines oficiais (Material Design e Human Interface Guidelines), utilizando Figma como ferramenta principal. O foco está na criação de protótipos interativos de alta fidelidade com entrega técnica para desenvolvedores.

## 📚 Material Teórico

### Tópico 1: Fundamentos de UI Mobile

#### Mobile vs Desktop — Diferenças Fundamentais

```
┌─────────────────────────────────────────────────────────┐
│              MOBILE vs DESKTOP                          │
├────────────────────────┬────────────────────────────────┤
│       MOBILE           │         DESKTOP                │
├────────────────────────┼────────────────────────────────┤
│ Tela: 360-428dp        │ Tela: 1280-1920px+             │
│ Interação: touch/gestos│ Interação: mouse/teclado       │
│ Contexto: em movimento │ Contexto: mesa/escritório      │
│ Atenção: fragmentada   │ Atenção: mais focada           │
│ Uma mão (geralmente)   │ Duas mãos + mouse             │
│ Vertical (portrait)    │ Horizontal (landscape)         │
│ Conexão: variável      │ Conexão: estável               │
│ Notificações: push     │ Notificações: menos intrusivas │
└────────────────────────┴────────────────────────────────┘
```

#### Thumb Zone — Zona de Conforto

```
┌─────────────────────────┐
│    THUMB ZONE MAP       │
│                         │
│  ┌───────────────────┐  │
│  │ 🔴 DIFÍCIL       │  │  ← Canto superior esquerdo
│  │                   │  │
│  │ 🟡 OK            │  │  ← Área intermediária
│  │                   │  │
│  │ 🟢 FÁCIL         │  │  ← Parte inferior
│  │ ████████████████ │  │  ← Barra de navegação
│  └───────────────────┘  │
│        👍 polegar       │
└─────────────────────────┘

REGRAS:
• Ações principais → zona verde (inferior)
• Navegação → bottom navigation bar
• Ações destrutivas → zona vermelha (difícil = proteção)
• Touch target mínimo: 48x48dp (Android) / 44x44pt (iOS)
```

#### Densidades de Tela

| Densidade | Android | iOS | Exemplo |
|-----------|---------|-----|---------|
| mdpi | 1x | - | Phones antigos |
| hdpi | 1.5x | - | Phones básicos |
| xhdpi | 2x | @2x | iPhone 8, muitos Androids |
| xxhdpi | 3x | @3x | iPhone 14, flagships |
| xxxhdpi | 4x | - | Flagships top |

**Unidades:**
- Android: `dp` (density-independent pixels) + `sp` (scale-independent pixels para texto)
- iOS: `pt` (points)
- Figma: use a escala 1x (360x800 para Android, 393x852 para iPhone 15)

### Tópico 2: Material Design 3 vs Human Interface Guidelines

#### Material Design 3 (Google/Android)

```
PRINCÍPIOS MATERIAL DESIGN 3:
┌─────────────────────────────────────────┐
│ 1. MATERIAL IS THE METAPHOR             │
│    Superfícies, elevação, sombras       │
│                                         │
│ 2. BOLD, GRAPHIC, INTENTIONAL           │
│    Tipografia forte, cores vibrantes    │
│                                         │
│ 3. MOTION PROVIDES MEANING             │
│    Animações com propósito              │
│                                         │
│ NOVIDADES DO MD3:                       │
│ • Dynamic Color (cores do wallpaper)    │
│ • Tokens de design unificados           │
│ • Componentes atualizados (FAB, Cards)  │
│ • Tipografia: Roboto → variável         │
└─────────────────────────────────────────┘

COMPONENTES ESSENCIAIS:
• Top App Bar (regular, large, medium)
• Bottom Navigation (3-5 itens, ícones + labels)
• FAB — Floating Action Button (ação principal)
• Cards (outlined, elevated, filled)
• Sheets (bottom sheet para conteúdo secundário)
• Chips (filter, input, suggestion)
• Snackbar (feedback temporário)
```

#### Human Interface Guidelines (Apple/iOS)

```
PRINCÍPIOS HIG:
┌─────────────────────────────────────────┐
│ 1. CLARITY                              │
│    Texto legível, ícones precisos       │
│                                         │
│ 2. DEFERENCE                            │
│    Conteúdo é o protagonista            │
│                                         │
│ 3. DEPTH                                │
│    Camadas visuais, hierarquia          │
│                                         │
│ PADRÕES iOS:                            │
│ • Tab Bar (inferior, até 5 itens)       │
│ • Navigation Bar (título + back)        │
│ • SF Symbols (ícones nativos)           │
│ • Blur effects (vibrancy)              │
│ • Haptic feedback                       │
│ • Safe Area (notch, Dynamic Island)     │
└─────────────────────────────────────────┘
```

#### Comparativo MD3 vs HIG

| Aspecto | Material Design 3 | Human Interface |
|---------|-------------------|-----------------|
| Navegação | Bottom Navigation Bar | Tab Bar |
| Botão principal | FAB (flutuante) | Botão no nav bar |
| Voltar | Seta ← na toolbar | Swipe from edge |
| Lista | RecyclerView com dividers | UITableView com disclosure |
| Alerta | Dialog/Snackbar | Alert/Action Sheet |
| Tipografia | Roboto (variável) | SF Pro (San Francisco) |
| Ícones | Material Symbols | SF Symbols |
| Cores | Dynamic Color (M3) | Tint Color + Dark Mode |

### Tópico 3: Design no Figma — Components e Auto Layout

#### Estrutura de Projeto Mobile no Figma

```
📁 Projeto Mobile
├── 📄 Cover (capa do projeto)
├── 📄 Design Tokens (cores, tipografia, spacing)
├── 📄 Components (biblioteca de componentes)
├── 📄 Wireframes (baixa fidelidade)
├── 📄 Screens (alta fidelidade)
├── 📄 Prototype (fluxos interativos)
└── 📄 Handoff (specs para devs)
```

#### Auto Layout — Conceitos

```
Auto Layout = Flexbox do Figma

┌─────────────────────────────────────┐
│  DIREÇÃO: Horizontal ↔ ou Vertical ↕│
│                                     │
│  SPACING: Espaço entre itens        │
│  PADDING: Espaço interno (T/R/B/L)  │
│                                     │
│  FILL: Item preenche o espaço       │
│  HUG: Container se ajusta ao conteúdo│
│  FIXED: Tamanho fixo                │
│                                     │
│  ALIGNMENT: Start, Center, End      │
│  DISTRIBUTION: Space Between        │
└─────────────────────────────────────┘

EXEMPLO — Botão com Auto Layout:
┌──────────────────────────────┐
│  [ícone] [texto do botão]    │  ← Horizontal, gap: 8
│   padding: 12 24 12 16       │  ← Padding vertical 12, horizontal 16/24
│   fill: container            │  ← Largura preenche o frame
└──────────────────────────────┘
```

#### Components e Variants

```
COMPONENT = Elemento reutilizável (como uma classe)
INSTANCE = Cópia vinculada (como um objeto)
VARIANT = Variação do mesmo componente

Exemplo: Componente "Button"
├── Variant: Type = Primary / Secondary / Tertiary
├── Variant: Size = Small / Medium / Large
├── Variant: State = Default / Hover / Pressed / Disabled
└── Variant: Icon = True / False

Total de combinações: 4 types × 3 sizes × 4 states × 2 icon = 96 variants!
(Figma gerencia tudo em um único componente)
```

#### Design Tokens

```
TOKENS = Valores reutilizáveis que formam a identidade visual

// Cores
--color-primary: #6750A4
--color-on-primary: #FFFFFF
--color-surface: #FFFBFE
--color-error: #B3261E

// Tipografia
--font-display-large: Roboto 57/64 -0.25
--font-headline-medium: Roboto 28/36 0
--font-body-large: Roboto 16/24 0.5
--font-label-medium: Roboto Medium 12/16 0.5

// Espaçamento
--spacing-xs: 4dp
--spacing-sm: 8dp
--spacing-md: 16dp
--spacing-lg: 24dp
--spacing-xl: 32dp

// Border Radius
--radius-sm: 8dp
--radius-md: 12dp
--radius-lg: 16dp
--radius-full: 100dp (pill shape)

// Elevação
--elevation-1: 1dp (cards)
--elevation-2: 3dp (app bar)
--elevation-3: 6dp (FAB)
--elevation-4: 8dp (bottom sheet)
```

### Tópico 4: Prototipagem Interativa

#### Tipos de Protótipo

| Nível | Ferramenta | Uso | Quando |
|-------|-----------|-----|--------|
| Sketch | Papel/lápis | Ideação rápida | Início do projeto |
| Low-fi | Figma (wireframe) | Testar fluxos | Após definir requisitos |
| Mid-fi | Figma (cinza + layout) | Validar estrutura | Antes do visual |
| High-fi | Figma (completo + animações) | Apresentar + testar | Antes de codar |
| Código | Android Studio | Produto final | Desenvolvimento |

#### Smart Animate no Figma

```
SMART ANIMATE = Figma interpola automaticamente entre dois estados

COMO USAR:
1. Criar Frame A (estado inicial)
2. Criar Frame B (estado final) — mesmos layers, posições diferentes
3. Conectar A → B com interação
4. Escolher "Smart Animate" como animação
5. Definir easing e duração

EXEMPLOS DE USO:
• Abrir/fechar menu lateral (translate X)
• Expandir card (scale + reposition)
• Like button (scale bounce)
• Tab switch (slide horizontal)
• Loading → Content (opacity + translate Y)

DICA: Nomear layers IGUAIS nos dois frames para Smart Animate funcionar!
```

#### Micro-interactions — Os 4 Momentos

```
Estrutura de uma micro-interaction (Dan Saffer):

1. TRIGGER → O que inicia a ação
   • Toque no botão
   • Pull-to-refresh
   • Shake do device

2. RULES → O que acontece
   • Formulário é enviado
   • Lista é atualizada
   • Feedback é mostrado

3. FEEDBACK → Como o usuário sabe que funcionou
   • Animação de check ✓
   • Vibração haptic
   • Cor muda (verde = sucesso)
   • Snackbar aparece

4. LOOPS & MODES → O que acontece depois
   • Animação para
   • Estado persiste
   • Timer reseta
```

### Tópico 5: Acessibilidade Mobile

#### Checklist de Acessibilidade Mobile

```
✅ CONTRASTE
  • Texto normal: ratio mínimo 4.5:1 (AA)
  • Texto grande (18px+): ratio mínimo 3:1
  • Elementos interativos: ratio 3:1 contra background
  • Ferramenta: Stark plugin (Figma) ou WebAIM Contrast Checker

✅ TOUCH TARGETS
  • Mínimo: 48x48dp (Android) / 44x44pt (iOS)
  • Espaçamento entre targets: 8dp mínimo
  • Nunca colocar ações destrutivas muito próximas

✅ TIPOGRAFIA
  • Tamanho mínimo: 12sp (Android) / 11pt (iOS)
  • Corpo de texto: 14-16sp recomendado
  • Suportar Dynamic Type (iOS) / Font Scale (Android)

✅ SCREEN READERS
  • Toda imagem ter alt text / contentDescription
  • Ordem de leitura lógica (top-down, left-right)
  • Ações acessíveis (não depender só de gestos complexos)
  • Headings para navegação por seções

✅ CORES
  • Não usar COR como único indicador de informação
  • Erro: não só vermelho, adicionar ícone ⚠️ + texto
  • Sucesso: não só verde, adicionar ícone ✓ + texto

✅ MOTION
  • Respeitar "Reduce Motion" do sistema
  • Não depender de animação para transmitir informação
  • Evitar piscar (flash) — pode causar convulsões
```

### Exercício 2: Design System Mobile (Semana 10)

**Objetivo:** Criar um Design System completo para projeto mobile.

**Requisitos do Design System:**
- [ ] Tokens de cor (primary, secondary, error, surface, background) — Light + Dark mode
- [ ] Escala tipográfica (display, headline, body, label) com fontes definidas
- [ ] Spacing scale (4, 8, 12, 16, 24, 32, 48)
- [ ] Border radius scale
- [ ] Componentes (mínimo 10): Button, Input, Card, Avatar, Badge, Chip, FAB, Bottom Nav, App Bar, Dialog

### Exercício 3: Protótipo Interativo (Semana 15)

**Objetivo:** Criar um protótipo de alta fidelidade com animações.

**App: "ETE Connect" — App de comunicação da escola**

Telas obrigatórias:
1. Splash screen com animação de entrada
2. Onboarding (3 telas com Smart Animate)
3. Login com validação visual (estados dos inputs)
4. Feed de avisos com pull-to-refresh
5. Perfil do aluno com foto e dados
6. Configurações com toggles animados

**Requisitos técnicos:**
- Smart Animate em pelo menos 3 transições
- Overlay para modal/bottom sheet
- Scroll em pelo menos 2 telas
- Micro-interaction em 1 elemento (like, save, etc.)

**Entrega:** Link do protótipo Figma + vídeo de demonstração (1min)

### Exercício 4: Auditoria de Acessibilidade (Semana 16)

**Objetivo:** Avaliar e corrigir problemas de acessibilidade em um app.

**Tarefas:**
1. Receber um design mobile com problemas de acessibilidade (fornecido pela professora)
2. Usar o plugin Stark (Figma) para verificar contrastes
3. Medir todos os touch targets (identificar os < 48dp)
4. Verificar hierarquia de leitura para screen reader
5. Listar todos os problemas encontrados (mínimo 10)
6. Corrigir o design e entregar versão acessível

**Entrega:** Relatório de auditoria + design corrigido no Figma

---

### Exercício 5: Handoff Completo (Semana 18)

**Objetivo:** Preparar um design para entrega a desenvolvedores.

**Tarefas:**
1. Pegar uma das telas do Exercício 3
2. Ativar Dev Mode no Figma
3. Documentar todas as specs: medidas, cores, fontes, espaçamentos
4. Exportar todos os assets (ícones SVG, imagens em 1x/2x/3x)
5. Criar anotações de comportamento (o que acontece ao clicar, scroll, etc.)
6. Gerar guia de edge cases (texto truncado, sem imagem, estado vazio, erro)

**Entrega:** Página de handoff no Figma + pasta com assets exportados

### 🅱️ Opção B: Atividades Desplugadas (Unplugged)

> 🎯 **Ideal quando:** Não há internet disponível OU alunos não têm smartphone

#### Atividade B1: "Audit de Interface no Celular"

| Item | Descrição |
|------|-----------|
| **Tema** | Análise de UX de apps reais usando critérios de design |
| **Duração** | 40 minutos |
| **Materiais** | Celular do aluno (sem internet necessária — apps já instalados), checklist impresso |
| **Objetivo** | Analisar UX de 3 apps instalados usando checklist de heurísticas |

**📋 Roteiro do Professor:**
1. (10 min) Revisar: 10 heurísticas de Nielsen adaptadas para mobile (thumb zone, feedback, consistência)
2. (5 min) Distribuir checklist impresso (1 por app a analisar)
3. (20 min) Alunos escolhem 3 apps JÁ instalados e preenchem checklist para cada um
4. (5 min) Ranking coletivo: qual app da turma tem melhor UX? Por quê?

**📱 Guia do Aluno — Checklist de Audit:**
- [ ] **Feedback:** O app responde visualmente a cada toque? (animação, cor, loading)
- [ ] **Consistência:** Botões do mesmo tipo têm o mesmo visual em todas as telas?
- [ ] **Thumb Zone:** Ações principais estão na parte inferior (alcançáveis com polegar)?
- [ ] **Touch Targets:** Botões têm pelo menos ~48dp? (não precisa medir, avaliar se é fácil acertar)
- [ ] **Hierarquia:** Fica claro o que é mais importante em cada tela?
- [ ] **Navegação:** É fácil voltar? Sabe sempre onde está?
- [ ] **Empty States:** O que aparece quando não tem conteúdo? (lista vazia, sem conexão)
- [ ] **Acessibilidade:** Contraste é suficiente? Fontes são legíveis?
- Nota final (1-10) para cada app + justificativa em 1 frase

#### Atividade B2: "Wireframe Mobile no Papel Quadriculado"

| Item | Descrição |
|------|-----------|
| **Tema** | Prototipagem de baixa fidelidade (wireframing) |
| **Duração** | 40 minutos |
| **Materiais** | Papel quadriculado, moldura 375×812 impressa (iPhone), lápis, borracha |
| **Objetivo** | Criar wireframes de 3 telas mobile respeitando proporções reais |

**📋 Roteiro do Professor:**
1. (10 min) Explicar: wireframe = esqueleto da interface. Sem cor, sem imagens reais, só estrutura. Mostrar exemplos.
2. (5 min) Distribuir molduras impressas (proporção iPhone 15: 393×852pt)
3. (20 min) Alunos desenham 3 telas do app AgendaPro: Login, Home (lista de agendamentos), Detalhes do agendamento
4. (5 min) Trocar com colega: "Consegue entender a tela sem explicação?" Se não, precisa simplificar.

**📱 Guia do Aluno:**
- Use a moldura impressa como sua "tela" (não desenhe fora dela!)
- Status bar no topo (horário, bateria) — NÃO redesenhe, apenas indique com linha
- Retângulos = imagens placeholder (X no centro)
- Linhas = texto (mais grossa = título, mais fina = corpo)
- Botão = retângulo arredondado com texto dentro
- Bottom Nav = barra inferior com 3-5 ícones simplificados
- NÃO se preocupe com beleza — foco é ESTRUTURA e FLUXO

#### Atividade B3: "Gesture Map"

| Item | Descrição |
|------|-----------|
| **Tema** | Mapeamento de gestos mobile e quando usar cada um |
| **Duração** | 40 minutos |
| **Materiais** | Folha A4, canetas coloridas, celular para referência |
| **Objetivo** | Mapear todos os gestos possíveis em mobile e definir quando usar cada um |

**📋 Roteiro do Professor:**
1. (10 min) Apresentar os gestos: tap, double-tap, long-press, swipe (4 direções), pinch, spread, rotate, drag
2. (5 min) Distribuir template com mão desenhada e áreas de gesto
3. (20 min) Para cada gesto, alunos documentam: nome, desenho do gesto, 2 exemplos de uso em apps reais, quando NÃO usar
4. (5 min) Quiz rápido: "Qual gesto para deletar item no Gmail?", "E para zoom no Maps?"

**📱 Guia do Aluno — Tabela de Gestos:**

| Gesto | Símbolo | Uso Comum | NÃO usar quando... |
|-------|---------|-----------|-------------------|
| Tap | 👆 | Selecionar, confirmar | — |
| Double-tap | 👆👆 | Zoom, like (Instagram) | Ação destrutiva |
| Long-press | 👆⏱️ | Menu contextual, selecionar múltiplos | Ação primária (é "escondido") |
| Swipe → | 👉 | Voltar (iOS), revelar ação | Navegação principal |
| Swipe ← | 👈 | Deletar (email), próximo | Ações sem confirmação |
| Pinch | 🤏 | Zoom out | — |
| Spread | 🖐️ | Zoom in | — |

#### Atividade B5: "Micro-interações com Stop-motion"

| Item | Descrição |
|------|-----------|
| **Tema** | Animação de interface e feedback visual |
| **Duração** | 40 minutos |
| **Materiais** | Folha A4 cortada em 4 pedaços, lápis, celular para fotografar |
| **Objetivo** | Desenhar 4 frames de uma animação de botão e fotografar em sequência |

**📋 Roteiro do Professor:**
1. (10 min) Explicar micro-interactions (Dan Saffer): Trigger → Rules → Feedback → Loops. Mostrar exemplos: botão de like, pull-to-refresh, loading
2. (5 min) Distribuir 4 pedaços de papel por aluno (= 4 frames de animação)
3. (20 min) Alunos desenham 4 frames de UMA micro-interação:
   - Frame 1: Estado default (botão normal)
   - Frame 2: Estado pressed (botão diminui levemente)
   - Frame 3: Estado de transição (animação/loading)
   - Frame 4: Estado final (sucesso — check aparece)
4. (5 min) Fotografar os 4 frames em sequência rápida no celular → ver como "animação"

**📱 Guia do Aluno:**
- Escolha UMA micro-interação: Like, Save, Add to Cart, Send, ou Loading
- Desenhe cada frame com PEQUENA diferença do anterior (princípio de animação)
- Dica: mantenha o mesmo enquadramento em todos os frames (use a moldura como guia)
- Fotografe os 4 frames e veja em sequência rápida no celular (modo galeria rápido)
- Bônus: criar GIF com app Stop Motion Studio (gratuito)

### 🅲 Opção C: Estudo de Caso / PBL (Problem-Based Learning)

> 🎯 **Ideal quando:** Aula geminada (2 horários seguidos) para debate aprofundado

#### Caso 1: "iOS vs Android — diferenças de padrão de interface"

| Item | Descrição |
|------|-----------|
| **Foco** | Platform conventions e decisões de design |
| **Formato** | Análise comparativa + debate (40-50 min) |
| **Conexão** | Semanas 1-5 (MD3 vs HIG) |

**Dinâmica:**
1. Professor apresenta: mesma app (Spotify, Instagram, ou WhatsApp) em Android e iOS — 5 capturas de cada
2. Perguntas: "O que muda?", "O que permanece?", "Por que o botão de voltar é diferente?"
3. Grupos de 4 preenchem tabela: Navegação, Tipografia, Ícones, Gestos, Feedback — como cada plataforma resolve
4. Debate: "Um designer deve criar UI diferente para cada plataforma ou manter igual?"

#### Caso 2: "Por que o Instagram mudou a barra de navegação"

| Item | Descrição |
|------|-----------|
| **Foco** | UX decisions baseadas em dados e negócio |
| **Formato** | Timeline + análise de motivações (40-50 min) |
| **Conexão** | Semanas 6-10 (navegação mobile, thumb zone) |

**Dinâmica:**
1. Professor mostra timeline: barra do Instagram 2016 (camera, home, search, like, profile) → 2020 (home, search, reels, shop, profile) → atual
2. Perguntas: "Por que Reels ganhou espaço? Por que Shop apareceu e sumiu? Thumb zone influenciou?"
3. Grupos analisam: decisões de negócio vs decisões de UX — quem ganha?
4. Exercício final: "Se você fosse redesenhar a barra HOJE, quais 5 itens colocaria? Justifique com dados de uso."

### 📊 Rubrica de Avaliação Adaptada (Atividades sem Laboratório)

| Critério | Excelente (10-9) | Bom (8-7) | Regular (6-5) | Insuficiente (<5) |
|----------|-----------------|-----------|---------------|-------------------|
| **Compreensão de UI/UX** | Demonstra domínio de guidelines e princípios | Boa compreensão com pequenas lacunas | Compreensão superficial | Não demonstra compreensão |
| **Qualidade do wireframe** | Proporcional, hierarquia clara, componentes corretos | Bom wireframe com pequenos erros | Wireframe básico/desorganizado | Ilegível ou incorreto |
| **Análise crítica** | Identifica problemas E propõe soluções fundamentadas | Identifica problemas corretamente | Análise superficial | Não identifica problemas |
| **Criatividade/Originalidade** | Solução inovadora respeitando guidelines | Solução boa e coerente | Solução genérica | Não apresenta solução |
| **Entrega/Documentação** | Completa, organizada, dentro do prazo | Completa com pequenos ajustes | Incompleta mas entregue | Não entregou |

> 💡 **Nota:** Atividades de contingência têm o **mesmo peso** das atividades regulares. Designers profissionais fazem sketches no papel antes de abrir o Figma!
