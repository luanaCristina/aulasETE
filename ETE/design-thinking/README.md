## 📋 Informações da Disciplina

| Item | Detalhe |
|------|---------|
| **Disciplina** | Design Thinking |
| **Módulo** | 1 (Semestre 1) |
| **Carga Horária** | 40 horas (2 aulas/semana) |
| **Duração** | 20 semanas |
| **Ferramentas** | Miro, Figma, Canva, Google Forms, Post-its |
| **Metodologia** | PBL (Problem-Based Learning) + Human-Centered Design |

### Ementa

Os 3 pilares do Design Thinking (Empatia, Colaboração, Experimentação) • As 5 etapas (Empatizar, Definir, Idealizar, Prototipar, Testar) • Técnicas de imersão e cocriação (brainstorming, storytelling, mapa de stakeholders) • Prototipagem rápida (papel, digital, MVP) • Validação com usuários • Apresentação de pitch.

### Competências a Desenvolver

- ✅ Compreender e aplicar os 3 pilares do Design Thinking em contextos reais
- ✅ Conduzir pesquisas de empatia utilizando entrevistas e observação
- ✅ Criar Mapas de Empatia, Personas e declarações POV (Point of View)
- ✅ Facilitar sessões de brainstorming e técnicas criativas (Crazy 8's, SCAMPER)
- ✅ Construir protótipos rápidos em papel e ferramentas digitais
- ✅ Testar soluções com usuários reais e iterar com base no feedback
- ✅ Comunicar ideias de forma persuasiva através de pitch e storytelling

> 💡 **Por que essa disciplina importa?** Startups de sucesso como Airbnb, Nubank e iFood nasceram a partir de processos de Design Thinking. A habilidade de identificar problemas reais, criar soluções criativas e validar com usuários é o que diferencia quem **constrói produtos que as pessoas amam** de quem apenas escreve código. Empresas buscam profissionais que pensem além da tecnologia.

## 📖 Material Teórico e Prático

### 1. Os 3 Pilares e 5 Etapas do Design Thinking

#### 🔍 Entendendo

O Design Thinking é uma abordagem **centrada no ser humano** para inovação, criada pela IDEO e popularizada pela d.school de Stanford. Diferente de métodos tradicionais (cascata), o DT é **iterativo e não-linear**.

**Os 3 Pilares:**

| Pilar | Significado | Na Prática |
|-------|-------------|------------|
| 🤝 **Empatia** | Compreender profundamente as pessoas | Sair do escritório, ouvir, observar |
| 👥 **Colaboração** | Co-criar com equipes multidisciplinares | Brainstorming, workshops, cocriação |
| 🧪 **Experimentação** | Testar cedo, errar rápido, aprender | Protótipos, MVPs, testes com usuários |

**As 5 Etapas:**

```
    ┌──────────────────────────────────────────────────────────────┐
    │                  DESIGN THINKING PROCESS                      │
    │                                                              │
    │  ❤️ EMPATIZAR    🎯 DEFINIR    💡 IDEALIZAR    🔨 PROTOTIPAR    ✅ TESTAR  │
    │                                                              │
    │  Entender o     Sintetizar    Gerar muitas   Construir      Validar     │
    │  problema do    e focar no    ideias sem     versões        com         │
    │  usuário        desafio       julgamento     rápidas        usuários    │
    │                                                              │
    │  Entrevistas    Persona       Brainstorm     Papel          Feedback    │
    │  Observação     POV           Crazy 8's      Figma          Iteração    │
    │  Shadowing      HMW           SCAMPER        MVP            Pivotar     │
    └──────────────────────────────────────────────────────────────┘
    
    ← ← ← ← ← ← ← ITERAÇÃO (voltar quantas vezes precisar) ← ← ← ← ← ← ←
```

> 💡 **DT vs Cascata vs Ágil:** No modelo cascata, você planeja tudo antes de construir. No ágil, você entrega em sprints. No Design Thinking, você **entende o problema antes de pensar na solução**. O DT complementa o ágil — use DT para descobrir O QUE construir, e ágil para COMO construir.

> ⚠️ **Atenção:** As etapas não são lineares! Você pode voltar da prototipagem para a empatia se descobrir que entendeu errado o problema. Isso é normal e esperado.

### 2. Mapa de Empatia e POV

#### 🔍 Entendendo

O **Mapa de Empatia** é uma ferramenta visual para organizar o que sabemos sobre nosso usuário. Ajuda a equipe a sair do "eu acho que..." para "eu ouvi/observei que...".

**Template do Mapa de Empatia:**

```
┌─────────────────────────────────────────────────────────────┐
│                    MAPA DE EMPATIA                           │
├──────────────────────────┬──────────────────────────────────┤
│   👀 O QUE VÊ?          │   👂 O QUE OUVE?                 │
│                          │                                  │
│  - Ambiente              │  - O que amigos dizem            │
│  - O que o mercado       │  - O que o chefe diz             │
│    oferece               │  - O que influenciadores         │
│  - O que amigos fazem    │    falam                         │
├──────────────────────────┼──────────────────────────────────┤
│   💬 O QUE FALA/FAZ?    │   🧠 O QUE PENSA/SENTE?         │
│                          │                                  │
│  - Atitude em público    │  - Preocupações                  │
│  - Comportamento         │  - Sonhos                        │
│  - Aparência             │  - Medos                         │
├──────────────────────────┴──────────────────────────────────┤
│  😣 DORES (frustrações, medos, obstáculos)                  │
├─────────────────────────────────────────────────────────────┤
│  🎯 GANHOS (desejos, necessidades, medidas de sucesso)      │
└─────────────────────────────────────────────────────────────┘
```

**Exemplo preenchido — Persona: "Lucas, 17 anos, quer aprender programação"**

```
┌─────────────────────────────────────────────────────────────┐
│          MAPA DE EMPATIA — Lucas, 17 anos                   │
├──────────────────────────┬──────────────────────────────────┤
│   👀 O QUE VÊ?          │   👂 O QUE OUVE?                 │
│                          │                                  │
│  - Amigos usando apps    │  - "Programação dá dinheiro"     │
│  - Youtubers de tech     │  - "É muito difícil aprender"    │
│  - Cursos caros online   │  - Pais: "faz faculdade logo"    │
├──────────────────────────┼──────────────────────────────────┤
│   💬 O QUE FALA/FAZ?    │   🧠 O QUE PENSA/SENTE?         │
│                          │                                  │
│  - Assiste tutoriais     │  - "Será que sou inteligente     │
│  - Começa cursos e       │    o suficiente?"                │
│    abandona              │  - Medo de não conseguir         │
│  - Pede dicas no Discord │  - Empolgado com tecnologia      │
├──────────────────────────┴──────────────────────────────────┤
│  😣 DORES: Cursos caros, inglês, falta de mentor,           │
│     não sabe por onde começar, se sente sozinho             │
├─────────────────────────────────────────────────────────────┤
│  🎯 GANHOS: Conseguir primeiro emprego em tech, criar       │
│     seu próprio app, ganhar independência financeira        │
└─────────────────────────────────────────────────────────────┘
```

**Declaração POV (Point of View):**

> **[USUÁRIO]** precisa de **[NECESSIDADE]** porque **[INSIGHT]**

Exemplo:
> **Lucas, estudante de 17 anos que quer aprender programação**, precisa de **um caminho de aprendizado estruturado e acessível em português** porque **se sente perdido diante de tantas opções e desiste por não ter orientação personalizada**.

**Perguntas "How Might We" (HMW):**
- Como poderíamos tornar o aprendizado de programação menos solitário?
- Como poderíamos ajudar iniciantes a escolher por onde começar?
- Como poderíamos transformar o medo de errar em motivação?

> 💡 **Dica:** Uma boa pergunta HMW não é nem ampla demais ("Como resolver a educação?") nem restrita demais ("Como fazer um botão azul?"). Ela deve abrir espaço para múltiplas soluções criativas.

### 3. Brainstorming e Crazy 8's

#### 🔍 Entendendo

**Brainstorming** é a técnica mais conhecida de ideação, mas a maioria das pessoas faz errado! Existem regras fundamentais para funcionar:

**7 Regras do Brainstorming (IDEO):**

| # | Regra | Explicação |
|---|-------|------------|
| 1 | Adie o julgamento | Nenhuma ideia é ruim neste momento |
| 2 | Encoraje ideias ousadas | Quanto mais louca, melhor (pode inspirar algo viável) |
| 3 | Construa sobre ideias dos outros | "Sim, E..." ao invés de "Sim, MAS..." |
| 4 | Foque no tema | Mantenha a pergunta HMW visível |
| 5 | Uma conversa por vez | Respeite quem está falando |
| 6 | Seja visual | Desenhe, use post-its, rabisque |
| 7 | Busque quantidade | Meta: 50+ ideias em 15 minutos |

**Crazy 8's — Técnica de Ideação Rápida:**

```
┌─────────────────────────────────────────────┐
│            CRAZY 8's (8 min)                │
│                                             │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐          │
│  │  1  │ │  2  │ │  3  │ │  4  │  ← 1 min │
│  │     │ │     │ │     │ │     │    cada   │
│  └─────┘ └─────┘ └─────┘ └─────┘          │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐          │
│  │  5  │ │  6  │ │  7  │ │  8  │           │
│  │     │ │     │ │     │ │     │           │
│  └─────┘ └─────┘ └─────┘ └─────┘          │
│                                             │
│  Dobre uma folha A4 em 8 partes.            │
│  1 minuto por quadrado = 1 ideia por min.   │
│  DESENHE, não escreva parágrafos!           │
└─────────────────────────────────────────────┘
```

**Exemplo de Output de uma sessão:**

Pergunta HMW: "Como poderíamos reduzir o desperdício de comida no refeitório?"

Ideias geradas (amostra das 50+):
1. App que mostra o cardápio do dia antes de ir
2. Sistema de "pedido antecipado" como restaurante
3. Porções P/M/G como Subway
4. Geladeira comunitária para sobras
5. Gamificação: ranking de menos desperdício por turma
6. Compostar resíduos para horta escolar
7. "Prato surpresa" com ingredientes que sobram
8. Parceria com ONG de alimentação

> ⚠️ **Erro comum:** Fazer brainstorming e já descartar ideias durante a sessão. SEPARE o momento de divergir (gerar ideias) do momento de convergir (selecionar ideias). São duas etapas diferentes!

### 4. Storytelling

#### 🔍 Entendendo

**Storytelling** é a arte de comunicar ideias através de narrativas. No Design Thinking, usamos storytelling para:
- Apresentar o problema de forma envolvente
- Contar a jornada do usuário
- Fazer um pitch convincente da solução

**Estrutura da Jornada do Herói (adaptada para produtos):**

```
┌─────────────────────────────────────────────────────┐
│         JORNADA DO HERÓI → PRODUTO                  │
│                                                     │
│  1. MUNDO COMUM                                     │
│     → Apresente o personagem e seu contexto         │
│                                                     │
│  2. O PROBLEMA (Chamado à Aventura)                 │
│     → Qual dor/frustração ele enfrenta?             │
│                                                     │
│  3. TENTATIVAS FRUSTRADAS                           │
│     → O que ele já tentou e não funcionou?          │
│                                                     │
│  4. A DESCOBERTA (Encontro com o Mentor)            │
│     → Ele encontra a sua solução/produto            │
│                                                     │
│  5. A TRANSFORMAÇÃO                                 │
│     → Como a vida dele mudou com o produto?         │
│                                                     │
│  6. O NOVO MUNDO                                    │
│     → Resultado final, impacto positivo             │
└─────────────────────────────────────────────────────┘
```

**Exemplo — Storytelling para pitch de um app de caronas escolares:**

> "Imagine a Maria, mãe solo que trabalha das 7h às 17h. Todo dia ela se preocupa: *como meu filho de 12 anos vai voltar da escola sozinho?* Ela já tentou apps de transporte, mas não confia em colocar uma criança sozinha num carro de estranho. Já pediu favores a vizinhos, mas sente vergonha de depender.
>
> Então ela descobriu o **CaronaSegura** — um app que conecta pais da mesma escola para revezar caronas, com verificação de identidade e rastreamento em tempo real.
>
> Hoje, Maria participa de um rodízio com 4 famílias. Seu filho volta seguro, ela economiza R$400/mês em transporte escolar, e ainda fez amizades no grupo de pais."

> 💡 **Dica:** Um bom storytelling faz o ouvinte SENTIR o problema antes de apresentar a solução. Se ele não se importar com o problema, não vai se interessar pela solução.

### 5. Prototipagem Rápida

#### 🔍 Entendendo

Prototipar é **dar forma a uma ideia** de maneira rápida e barata, para que possamos testá-la antes de investir tempo e dinheiro na construção real.

**Níveis de Fidelidade:**

| Nível | O que é | Quando usar | Tempo | Ferramenta |
|-------|---------|-------------|-------|------------|
| 🟢 Baixa | Rabiscos em papel, post-its | Início, muitas ideias para testar | 10–30 min | Papel e caneta |
| 🟡 Média | Wireframes digitais, telas simples | Já definiu o fluxo principal | 2–4 horas | Figma (wireframe) |
| 🔴 Alta | Protótipo clicável, visual final | Teste com usuários, pitch | 1–2 dias | Figma (hi-fi) |

**Exemplo de Protótipo em Papel (5 telas de um app):**

```
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ TELA 1   │  │ TELA 2   │  │ TELA 3   │  │ TELA 4   │  │ TELA 5   │
│          │  │          │  │          │  │          │  │          │
│ [Logo]   │  │ Lista de │  │ Detalhes │  │ Confirmar│  │ Sucesso! │
│          │  │ opções:  │  │ do item: │  │          │  │          │

### 6. Pitch de Produto

#### 🔍 Entendendo

O **pitch** é a apresentação curta e persuasiva da sua ideia. Em competições de startup, você tem entre 3 e 5 minutos para convencer uma banca. A estrutura mais usada:

**Estrutura do Pitch (5 blocos):**

| Bloco | Duração | O que falar |
|-------|---------|-------------|
| 🪝 **Hook** | 15 seg | Frase de impacto ou estatística chocante |
| 😣 **Problema** | 45 seg | Dor real de pessoas reais (com dados) |
| 💡 **Solução** | 60 seg | O que vocês construíram e como funciona |
| 📊 **Evidências** | 45 seg | Resultados dos testes, feedback de usuários |
| 🎯 **CTA (Call to Action)** | 15 seg | O que você pede: voto, investimento, apoio |

**Exemplo de Script de Pitch (2 minutos):**

> **Hook:** "35% da comida produzida no Brasil vai para o lixo. Na nossa escola, são 15kg de alimento desperdiçados POR DIA."
>
> **Problema:** "Conversamos com 20 alunos e descobrimos que a maioria joga comida fora porque recebe porções grandes de algo que não gosta, e não pode escolher."
>
> **Solução:** "Criamos o *EscolhaPrato* — um sistema simples onde o aluno marca no celular, no dia anterior, o que quer comer. A cozinha prepara sob demanda."
>
> **Evidências:** "Testamos com 3 turmas por uma semana. O desperdício caiu 40%. Os cozinheiros economizaram 2 horas de preparo. 92% dos alunos aprovaram."
>
> **CTA:** "Precisamos do apoio da direção para implementar na escola inteira no próximo semestre. Quem está conosco?"

> 💡 **Elevator Pitch (30 segundos):** Se você encontrasse um investidor no elevador, o que diria? Treine a versão ultra-curta: "Para [público] que [problema], nosso [produto] faz [solução], diferente de [alternativas] porque [diferencial]."

## ✏️ Exercícios Práticos

### A1 — Mapa de Empatia (Fácil) 🟢

**Objetivo:** Aplicar o Mapa de Empatia entrevistando uma pessoa real.

**Instruções:**
1. Forme duplas
2. Entreviste seu colega sobre: "Como é o seu trajeto diário até a escola?"
3. Use perguntas abertas (mínimo 10 minutos de conversa)
4. Preencha o Mapa de Empatia com base no que OUVIU (não no que você acha)
5. Escreva uma declaração POV

**Critérios de avaliação:**
- Mapa preenchido com informações reais da entrevista (não inventadas)
- Distinção clara entre o que a pessoa DISSE vs o que você INTERPRETOU
- POV bem formulado (usuário + necessidade + insight)

<details>
<summary>📋 Rubrica de Avaliação</summary>

| Critério | Excelente (10) | Bom (7) | Insuficiente (4) |
|----------|---------------|---------|-----------------|
| Entrevista | 10+ min, perguntas abertas, escuta ativa | 5-10 min, algumas perguntas fechadas | < 5 min, perguntas sim/não |
| Mapa de Empatia | 4 quadrantes preenchidos com riqueza | 3 quadrantes completos | Informações genéricas/inventadas |
| Dores e Ganhos | Específicos, baseados em falas reais | Parcialmente específicos | Genéricos ou copiados |
| Declaração POV | Segue formato, insight genuíno | Formato correto, insight raso | Formato errado ou ausente |

</details>

---

### A2 — Brainstorming Coletivo (Médio) 🟡

**Objetivo:** Conduzir uma sessão de brainstorming seguindo as 7 regras e gerar 20+ ideias.

**Desafio:** "How Might We — Como poderíamos reduzir o desperdício de comida no refeitório da escola?"

**Instruções:**
1. Forme equipes de 4-5 pessoas
2. Escolham um facilitador (controla tempo e regras)
3. Coloquem a pergunta HMW bem visível
4. 15 minutos de brainstorming (1 ideia por post-it)
5. Agrupem ideias similares (clusters)
6. Votem: cada pessoa tem 3 dots (adesivos) para votar
7. Selecionem as top 3 ideias mais votadas

**Critérios de avaliação:**
- Quantidade mínima: 20 ideias geradas
- Variedade (ideias não repetitivas)
- Seleção justificada das top 3

<details>
<summary>📋 Rubrica de Avaliação</summary>

| Critério | Excelente (10) | Bom (7) | Insuficiente (4) |
|----------|---------------|---------|-----------------|
| Quantidade | 30+ ideias | 20-29 ideias | < 20 ideias |
| Variedade | Ideias em 5+ categorias diferentes | 3-4 categorias | Todas muito parecidas |
| Processo | Regras seguidas, facilitador atuou | Maioria das regras seguidas | Brainstorming desorganizado |
| Seleção | Top 3 com justificativa clara | Top 3 sem justificativa | Sem priorização |

</details>

---

### A3 — Crazy 8's para App Local (Médio) 🟡

**Objetivo:** Criar 8 sketches rápidos de telas para um app que resolve um problema local.

**Instruções:**
1. Escolha um problema local (transporte, segurança, saúde, educação)
2. Escreva uma pergunta HMW
3. Dobre uma folha A4 em 8 partes iguais
4. Timer de 8 minutos (1 min por quadrado)
5. DESENHE uma ideia diferente de tela/solução em cada quadrado
6. Não se preocupe com estética — rabiscos rápidos!
7. Apresente seus 8 sketches para a equipe em 2 minutos

**Critérios de avaliação:**
- 8 sketches completos (todos preenchidos)
- Ideias variadas (não 8 versões da mesma tela)
- Problema real e relevante

<details>
<summary>📋 Rubrica de Avaliação</summary>

| Critério | Excelente (10) | Bom (7) | Insuficiente (4) |
|----------|---------------|---------|-----------------|
| Completude | 8/8 sketches preenchidos | 6-7 sketches | < 6 sketches |
| Variedade | 8 abordagens diferentes | 5-6 diferentes | Repetitivos |
| Relevância | Problema real e local | Problema genérico | Problema fictício/irrelevante |
| Comunicação | Sketches compreensíveis | Maioria compreensível | Ilegíveis |

</details>

---

### A4 — Protótipo em Papel + Teste (Desafiador) 🔴

**Objetivo:** Construir protótipo de 5 telas em papel, testar com 3 pessoas e documentar aprendizados.

**Instruções:**
1. Baseado na melhor ideia do Crazy 8's, desenhe 5 telas em papel (tamanho celular)
2. Defina o fluxo: qual tela leva a qual?
3. Teste com 3 pessoas que NÃO são da sua equipe
4. Para cada teste: dê uma tarefa ("faça X"), observe, anote
5. Documente: O que funcionou? O que confundiu? O que mudar?

**Critérios de avaliação:**
- 5 telas com fluxo lógico
- 3 testes realizados com pessoas diferentes
- Documentação de insights e melhorias

<details>
<summary>📋 Rubrica de Avaliação</summary>

| Critério | Excelente (10) | Bom (7) | Insuficiente (4) |
|----------|---------------|---------|-----------------|
| Protótipo | 5+ telas, fluxo claro, interativo | 5 telas básicas | < 5 telas ou sem fluxo |
| Testes | 3 pessoas, roteiro, observação documentada | 2 pessoas testaram | 1 ou nenhum teste |
| Documentação | Insights claros + plano de iteração | Alguns insights | Sem documentação |
| Iteração | Fez mudanças baseadas no feedback | Identificou mudanças | Não usou o feedback |

</details>

---

### A5 — Pitch de 2 Minutos (Desafiador) 🔴

**Objetivo:** Escrever e apresentar um pitch de 2 minutos para a solução da equipe.

**Instruções:**
1. Use a estrutura: Hook → Problema → Solução → Evidências → CTA
2. Escreva o roteiro completo (máximo 300 palavras)
3. Crie 3-5 slides de apoio no Canva (pouco texto, muito visual)
4. Ensaie 3 vezes cronometrando (máximo 2 min)
5. Apresente para a turma OU grave em vídeo

**Critérios de avaliação:**
- Estrutura do pitch seguida
- Tempo respeitado (1:30 a 2:00)
- Comunicação clara e envolvente
- Slides visuais (não slides de texto)

<details>
<summary>📋 Rubrica de Avaliação</summary>

| Critério | Excelente (10) | Bom (7) | Insuficiente (4) |
|----------|---------------|---------|-----------------|
| Estrutura | 5 blocos presentes e bem conectados | 4 blocos presentes | < 4 blocos ou desordenado |
| Tempo | 1:30–2:00 | 2:00–2:30 | > 3:00 ou < 1:00 |
| Comunicação | Envolvente, contato visual, confiante | Clara mas monótona | Leitura de texto, tímida |
| Slides | Visuais, impactantes, pouco texto | Funcionais | Slides de texto cheio |
| Evidências | Dados reais dos testes com usuários | Dados parciais | Sem dados/evidências |

</details>

> - Dividam falas entre todos os integrantes

**Questão 7 (2,0).** Analise o caso abaixo e identifique qual etapa do Design Thinking foi IGNORADA:

*"Uma startup criou um app de receitas saudáveis para jovens. Investiram 6 meses no desenvolvimento com design bonito e muitas funcionalidades. ### 🎨 Opção B: Atividades Desplugadas (Unplugged)

> 🎯 **Objetivo:** Realizar atividades de Design Thinking usando apenas materiais analógicos — cartolina, post-its, canetas, papel A4, tesoura e materiais recicláveis.

#### Atividade B1: "Mapa de Empatia em Cartolina"

> **Conexão curricular:** Etapa 1 — Empatizar | Técnica: Mapa de Empatia

**📋 Roteiro do Professor (50 min):**

| Tempo | Ação | Fala sugerida |
|:-----:|------|---------------|
| 0–5 min | Distribuir cartolina A3 e canetas coloridas | "Cada grupo vai construir o mapa de empatia da persona do nosso projeto AgendaPro" |
| 5–10 min | Desenhar o template no quadro (4 quadrantes + dores/ganhos) | "Copiem essa estrutura na cartolina" |
| 10–15 min | Explicar cada quadrante com exemplos | "No 'O que pensa/sente' vão os medos e sonhos — coisas que a pessoa não fala em voz alta" |
| 15–35 min | Grupos preenchem o mapa baseado em entrevistas já realizadas | Circular entre grupos, provocar: "Como vocês sabem disso? O usuário DISSE ou vocês SUPÕEM?" |
| 35–45 min | Cada grupo apresenta seu mapa (2 min por grupo) | "Mostrem o insight mais surpreendente que encontraram" |
| 45–50 min | Discussão: semelhanças e diferenças entre os mapas | "O que todos os grupos encontraram em comum? Isso é um PADRÃO importante!" |

**📋 Guia do Aluno:**

```
┌─────────────────────────────────────────────────────────────┐
│  🗺️ ATIVIDADE: MAPA DE EMPATIA EM CARTOLINA               │

│                                                             │
│  PASSO A PASSO:                                             │
│  1. Dividam a cartolina em 6 seções (ver modelo no quadro) │
│  2. Escolham a persona do AgendaPro (aluno da ETE)         │
│  3. Preencham CADA quadrante com base nas entrevistas:     │
│     - O que VÊ? (ambiente, redes sociais, amigos)          │
│     - O que OUVE? (conselhos, críticas, influências)       │
│     - O que FALA/FAZ? (atitudes, comportamentos)           │
│     - O que PENSA/SENTE? (medos, sonhos, frustrações)      │
│  4. Dores: 3 maiores frustrações                           │
│  5. Ganhos: 3 maiores desejos                              │
│  6. Preparem apresentação de 2 min                         │

#### Atividade B2: "Crazy 8's no Papel"

> **Conexão curricular:** Etapa 3 — Idealizar | Técnica real do Design Sprint (Google Ventures)

**📋 Roteiro do Professor (30 min):**

| Tempo | Ação | Fala sugerida |
|:-----:|------|---------------|
| 0–3 min | Distribuir folha A4 e explicar a técnica | "Dobrem a folha em 8 partes iguais. Vocês terão exatamente 1 minuto para cada quadrado — DESENHEM, não escrevam!" |
| 3–5 min | Definir o desafio HMW no quadro | "Como poderíamos ajudar o aluno da ETE a organizar seus horários e tarefas?" |
| 5–13 min | TIMER: 8 minutos cronometrados (avisar a cada minuto) | "Próximo! Não pense demais — a primeira ideia que vier!" |
| 13–20 min | Cada aluno escolhe sua melhor ideia e apresenta em 30 seg | "Qual das 8 vocês desenvolveriam? Por quê?" |
| 20–28 min | Votação silenciosa: 3 dots por pessoa (bolinhas de caneta) | "Votem nas ideias dos OUTROS que vocês acham mais promissoras" |
| 28–30 min | Revelar as mais votadas e discutir | "Temos nossas ideias finalistas! Na próxima etapa, vamos prototipar a vencedora" |

**📋 Guia do Aluno:**

```
┌─────────────────────────────────────────────────────────────┐
│  ⚡ CRAZY 8's — 8 IDEIAS EM 8 MINUTOS                      │
│                                                             │
│  MATERIAL: 1 folha A4, caneta/lápis, cronômetro            │
│                                                             │
│  COMO FUNCIONA:                                             │
│  1. Dobre a folha em 8 retângulos iguais                   │
│  2. A professora vai cronometrar: 1 MINUTO por quadrado    │
│  3. Em cada quadrado, DESENHE uma solução diferente         │
│  4. Pode ser: tela de app, fluxo, objeto, serviço...       │
│  5. NÃO escreva parágrafos — use DESENHOS + palavras-chave │
│  6. Quando acabar: circule sua favorita com caneta grossa   │
│                                                             │
│  💡 DICAS:                                                  │
│  - Não julgue suas ideias — quantidade > qualidade!         │
│  - Se travar, pense: "E se fosse para crianças?"           │
│    "E se fosse de graça?" "E se fosse mágico?"             │
│  - Rabiscos FEIOS estão liberados! Isso não é aula de arte │
└─────────────────────────────────────────────────────────────┘
```

**Materiais necessários:** Folha A4 (1 por aluno), canetas, cronômetro (celular da professora)

#### Atividade B3: "How Might We com Post-its"

> **Conexão curricular:** Etapa 2 — Definir | Técnica: Reframe de problemas em oportunidades

**📋 Roteiro do Professor (35 min):**

| Tempo | Ação | Fala sugerida |
|:-----:|------|---------------|
| 0–5 min | Explicar o conceito de HMW no quadro com 3 exemplos | "HMW transforma PROBLEMAS em OPORTUNIDADES de design" |
| 5–8 min | Apresentar o problema: insights da pesquisa de empatia | "Nossos usuários disseram que: [ler 3 insights do mural]" |
| 8–18 min | Cada aluno escreve 3 HMW em post-its (1 por post-it) | "Comecem com 'Como poderíamos...' e terminem com algo aberto, não com solução" |
| 18–25 min | Colar post-its no quadro e agrupar por tema | "Vamos organizar: juntem os que falam de coisas parecidas" |
| 25–32 min | Votação por pontos: 3 dots por pessoa | "Coloquem um ponto nos HMW que vocês acham mais inspiradores para gerar soluções" |
| 32–35 min | Selecionar os top 3 HMW para próxima etapa | "Estes serão nossos desafios para a ideação!" |

**📋 Guia do Aluno:**

```
┌─────────────────────────────────────────────────────────────┐
│  ❓ HOW MIGHT WE — COMO PODERÍAMOS...?                     │
│                                                             │
│  MATERIAL: 3 post-its por pessoa, caneta grossa             │
│                                                             │
│  REGRAS DO HMW:                                             │
│  ✅ Comece com "Como poderíamos..."                         │
│  ✅ Seja específico o suficiente para inspirar ideias       │
│  ✅ Seja aberto o suficiente para ter múltiplas respostas   │
│  ❌ NÃO coloque a solução na pergunta!                     │
│                                                             │
│  EXEMPLOS:                                                  │
│  ❌ "Como poderíamos criar um app de agenda?" (= solução)  │
│  ✅ "Como poderíamos ajudar alunos a não perder prazos?"   │
│                                                             │
│  PASSOS:                                                    │
│  1. Escreva 3 perguntas HMW (1 por post-it, letra grande)  │
│  2. Cole no quadro quando a professora pedir               │
│  3. Ajude a organizar por temas                            │
│  4. Vote com 3 pontos (pode colocar todos em 1 ou dividir) │
└─────────────────────────────────────────────────────────────┘
```

**Materiais necessários:** Post-its (3 por aluno), canetas grossas, parede/quadro para colar

#### Atividade B5: "Pitch de 1 Minuto"

> **Conexão curricular:** Bloco 4 — Comunicação e Pitch | Técnica: Elevator Pitch

**📋 Roteiro do Professor (40 min):**

| Tempo | Ação | Fala sugerida |
|:-----:|------|---------------|

### 📊 Opção C: Estudo de Caso / PBL (Problem-Based Learning)

> 🎯 **Objetivo:** Analisar casos reais de Design Thinking no mundo real, debater decisões e extrair aprendizados aplicáveis ao projeto da turma.

#### Caso 1: "Design Sprint do Google — 5 dias para resolver um problema"

**Contexto para discussão:**
Em 2010, Jake Knapp (Google Ventures) criou o método Design Sprint: resolver um problema complexo em apenas 5 dias, sem meses de reuniões. O método foi usado em +150 startups e dentro do Google para criar produtos como Gmail e Google Maps.

**Material para imprimir/projetar:**
- Dia 1 (Segunda): Mapear o problema e escolher um foco
- Dia 2 (Terça): Sketches individuais de soluções (Crazy 8's!)
- Dia 3 (Quarta): Decidir qual solução prototipar
- Dia 4 (Quinta): Construir protótipo realista em 1 dia
- Dia 5 (Sexta): Testar com 5 usuários reais

**Perguntas para debate (30 min):**
1. Por que limitar a 5 dias funciona melhor do que "o tempo que precisar"?
2. No dia 2, cada pessoa faz sketch INDIVIDUAL antes de mostrar ao grupo. Por que não fazer brainstorming coletivo direto?
3. Só 5 usuários no teste. Isso é suficiente? (Referência: Nielsen diz que 5 encontram 85% dos problemas)
4. Como poderíamos aplicar uma versão de 5 AULAS do Design Sprint no nosso projeto?

---

#### Caso 2: "Redesign do Pix pelo Banco Central"

**Contexto para discussão:**
O Pix foi lançado em novembro/2020 e em 2 anos teve adesão de 130+ milhões de brasileiros. O Banco Central usou princípios de Design Centrado no Usuário: pesquisou dores (TED/DOC caros, demora), ideou (pagamento instantâneo 24/7), prototipou (piloto com bancos) e testou iterativamente.

**Material para imprimir/projetar:**
- Problema anterior: TED custava R$8-20, só em horário comercial, 1-2 dias para cair
- Pesquisa: 70% dos brasileiros queriam transferência gratuita e instantânea
- Design decisions: QR Code, chaves (CPF/celular/email), sem custo PF
- Resultado: 140 milhões de usuários em 3 anos, 3 bilhões de transações/mês

**Perguntas para debate (30 min):**
1. Que DORES dos usuários o Pix resolveu? (Conecte com Mapa de Empatia)
2. O QR Code do Pix é uma decisão de DESIGN. Por que não pedir dados bancários completos?
3. A chave Pix (CPF, celular, email) é uma ABSTRAÇÃO. O que ela esconde do usuário?
4. Se vocês fossem redesenhar o Pix para menores de 18 anos, que pesquisa fariam primeiro?
